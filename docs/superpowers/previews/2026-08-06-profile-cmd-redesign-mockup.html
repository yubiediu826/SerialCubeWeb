SerialCube v4.9 方案/命令双层架构 PROPOSAL

从 "Protocol = (kind + fields + cmd)" 一对一 → 拆成 "方案 (Profile) + 命令 (Command)" 多对一

数据模型变化 (v4.8c → v4.9)

方案 Profile 新增

  • 名称 (string)
  • 协议类型 (kind: 0-7)
  • 帧字段 (fields, kind 模板)
  • CRC 设置 (type / init / endian / range)
  • 数据字段定义 (dataFields, 跨命令共享)
  • 字节序默认 (proto.byteOrder)
→ 一份方案,所有命令复用

命令 Command 重构

  • 名称 (string)
  • 引用方案 (profileId, FK)
  • 方向 (tx / rx)
  • cmd byte (0x00-0xFF)
  • 触发方式 (none / manual / timer / pair)
  • 数据字段映射 (引用方案的 dataFields 子集)
  • 仪表盘绑定 (显示/隐藏, 卡片 ID)
  • ack 期望 (触发方式 = pair 时)
→ 多命令共享 1 方案

仪表盘 改

  • 顶栏"方案"tab 切换 (替代 cmd tab)
  • 选中方案 → 显示该方案下所有命令卡片
  • 切方案 = 切整套协议解析
  • 无需再编辑 cmd 的 protocol 引用
→ 用户视角: 一个方案一组卡片

核心变化与工作流 (v4.8c → v4.9)

  • 方案 (Profile) = 协议类型 (kind) + 帧字段 + CRC + 数据字段定义。1 个方案对应 1 套物理协议 (例如 "Modbus RTU 主栈")。
  • 命令 (Command) = 引用方案 + 方向 + cmd byte + 触发方式 + 仪表盘绑定 + 数据字段映射 (从方案字段池里选子集)。
  • 仪表盘 顶栏从"cmd tab"改成"方案 tab" — 切方案 = 切整套解析, 无需碰 cmd。
  • 新增命令工作流: 选中方案 → "+ 新建命令" → 弹命令编辑器 (引用方案, 选 cmd byte, 选字段池) → 完成。不需要新建方案。
  • 修改协议字段: 选中方案 → 改 fields → 自动应用到该方案所有命令。不需要逐个改 cmd 关联的 protocol。
  • 数据迁移: v4.8c 现状 2 协议 (BMS TLV / Modbus RTU) 启动时自动转成 2 个方案, 每个方案保留原 1 个 cmd (历史 cmd 1:1 落到方案下)。

兼容性约束 (AGENTS.md §2 强制, 不动)

  • localStorage keys: serialweb:prefs / serialweb:version-modal-seen / wsl-*
  • 配置 JSON type: SerialWebUserConfig v1 → 升级到 v2 (加 profileId 字段, 启动时 v1 → v2 自动迁移)
  • .timeline 二进制 magic: WSLBIN1 (不动)
  • API 路径: /api/serialweb_page-view (不动)
