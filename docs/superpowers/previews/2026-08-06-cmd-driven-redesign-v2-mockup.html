改协议字段的工作流 (对比 v4.8c)

  • v4.8c 现状: 改 BMS TLV 协议 → 只能改那个 tab,如果 cmd 引用了别的 protocol (BMS 1# 引用 BMS TLV, BMS 2# 引用 BMS TLV v2...),要逐个 cmd 跳回去重新选 protocol。
  • v4.9 v2 改进: 选中"读取 1# 电压"命令 → 编辑 → 改 kind 7 fields → 保存 → 自动归到 BMS TLV 方案 → BMS TLV 方案下所有 4 个命令的 fields 同步更新。
  • 真实场景: 用户改 header 0xAA → 0xBB 一次 → BMS TLV 方案 4 个命令全部生效。

数据模型 (隐式方案)

  • 命令 = 名称 / 方向 / cmd byte / 触发 / 协议定义 (kind + fields + CRC) / 数据字段定义 / 仪表盘绑定
  • 方案 (隐式) = NS._getImplicitProfile(kind, fieldsHash, crcConfig) → 同 kind + 同 fields + 同 CRC 的命令归一组
    • 不存独立 PROFILE 对象, 派生计算
    • 命名 = "kind N · {kindName}"(自动) 或用户改名(存到 commands[0].profileName, 其他共享命令显示同组名)
  • 改协议字段 = 改任意一个命令的 kind/fields/CRC → 系统检测到"同组"命令 → 提示"将影响该方案 N 个命令,确认?"
  • 数据迁移 (兼容 v1 user config): 启动时把 v1 protocols 转成 v2 commands, 每个 protocol 1 个 cmd,自动归组

兼容性约束 (AGENTS.md §2 强制, 不动)

  • localStorage keys: serialweb:prefs / serialweb:version-modal-seen / wsl-*
  • 配置 JSON type: SerialWebUserConfig v1 → v2 (加 commands 数组, 启动时 v1 → v2 自动迁移)
  • .timeline 二进制 magic: WSLBIN1 (不动)
  • API 路径: /api/serialweb_page-view (不动)
