# v1.3.18 — 串口日志断帧 + 默认 hex + 下拉框高度统一 (2026-08-17)

## 概述

3 项设备连接管理相关改进一波:
1. **组帧超时 (新功能)** — 解决从机接收串口日志不自动断帧挤在一块的问题。`queueRxBytes` 加 idle 计时器, 无新字节超过阈值自动 finalize 当前累积行
2. **默认 hex RX/TX** — `state.settings.sendMode` 默认 'ascii' → 'hex', `state.settings.textEncoding` 默认 'utf-8' → 'hex', text-encoding select 加 'hex' 选项。仅初始默认值, 用户可切
3. **下拉框高度统一** — `.config-panel .field select/input` padding 从 7px 升到 9px, 跟 `.baud-rate-combo` 一致

## 改动

### A. 组帧超时 (主改动)

**问题**: 从机连续发 8B 帧 `5A 01 01 02 00 00 91 1D` (无换行), `queueRxBytes` 全部进同一个 `rxActiveEvent`, 长度超限才 roll over。中间没有"帧间 gap"切分, 用户看到的是长串挤压。

**方案**: idle 计时器 (推荐), 默认 50ms, 范围 0-2000ms (0 = 关 = 当前行为)。

#### A.1 HTML — 新字段

在 `SerialCube.html` line 7883 (parity 之后) 加:

```html
<div class="field">
  <label for="frame-timeout">组帧超时</label>
  <input id="frame-timeout" type="number" min="0" max="2000" step="10" value="50">
</div>
```

`.config-grid` (line 7839 容器) CSS 改 grid-template-columns 从 4 col → 5 col (1 行 CSS)。

#### A.2 State + 持久化

`state.settings.frameTimeout = 50` (默认), 0-2000 整数。

**持久化模型**: `state.settings` 当前不走 `_saveUserConfig` (那存 protocols/cards/alerts/activeProtoId/simRole)。新加独立 localStorage key `serialcube.frameTimeout` (独立 key 不动现有 userConfig 逻辑)。

加载顺序: `localStorage.getItem('serialcube.frameTimeout')` → 兜底默认 50。保存时机: input `change` 事件 (用户改完失焦)。

> 注: 后续如果 `state.settings` 全部走统一持久化 (跟 baudRate 等), 可在 v1.3.19 改 `_saveUserConfig` 一并处理。

#### A.3 JS — 计时器逻辑

**入口** (line 24177 `queueRxBytes` 顶部): 如果有 `rxActiveEvent` 且 `frameTimeout > 0`, 启 setTimeout。

```javascript
function scheduleFrameTimeout() {
  if (!state.serial._frameTimeoutId) {
    state.serial._frameTimeoutId = setTimeout(flushFrameByTimeout, state.settings.frameTimeout);
  }
}
function flushFrameByTimeout() {
  state.serial._frameTimeoutId = null;
  if (state.serial.rxActiveEvent) {
    finalizeRxActiveEvent(nowPreciseMs(), { processRules: true, syntheticSplit: true });
  }
}
```

**新字节来** (line 24186 `upsertLine` 入口): clear + restart。

```javascript
if (state.settings.frameTimeout > 0) {
  clearTimeout(state.serial._frameTimeoutId);
  state.serial._frameTimeoutId = setTimeout(flushFrameByTimeout, state.settings.frameTimeout);
}
```

**disconnect** (line ~24123 `disconnectSerial`): clearTimeout + 主动 finalize, 避免 disconnect 时丢失尾巴字节。

**input 变化** (input 字段 `change` 事件, 失焦后): clearTimeout + 写 localStorage + 重新 schedule (用新值)。`change` 而非 `input` — 失焦/回车才生效, 避免用户每键入一位数字都重置 timer。

#### A.4 风险 + 边界

| 项 | 风险 | 缓解 |
|----|------|------|
| 0ms 默认 | 无新行为 | 跟之前一样 |
| 50ms 默认误断 | 极慢设备 (>50ms 帧间) 误断 | 用户可调 0-2000ms |
| disconnect 时尾巴字节 | rxActiveEvent 仍可能有未提交 | disconnect handler clearTimeout + finalize |
| hex 默认 + 已存 user config | user config 覆盖默认 | 不强制迁移, 读时无即用默认 |
| input 拖值时旧计时器 | 用户输入到 change 期间被旧 timer finalize | `change` 事件 clear 旧 timer |

**协议解析器不受影响**: 协议解析走 `tryDispatchAckFrames` 自己的 header/length/CRC, 不依赖 `rxActiveEvent`。

## 数据流

### Frame timeout 数据流

```
Web Serial readLoop (line 25392)
  ↓ bytes
queueRxBytes (line 24177)
  ├─ for each byte: upsertLine → appendRxSegmentToEvent → state.serial.rxActiveEvent
  ├─ schedule new setTimeout (clearTimeout old)
  └─ if newline (0x0d/0x0a) → finalizeRxActiveEvent → 清 timer + 新 event
  ↓
[setTimeout fires after frameTimeout ms with no new bytes]
  ↓
flushFrameByTimeout → finalizeRxActiveEvent → rxActiveEvent → 落 1 行 log
```

### Hex default 数据流

```
localStorage.serialcube.textEncoding
  ↓ 加载 (无 → 默认 'hex')
state.settings.textEncoding
  ↓
decodeBytes (line 9831) → 'hex' 分支 → bytesToRawHex
  ↓
event.text / event.hex 字段 → log 显示
```

## 兼容性

- **不破坏现有行为**: 0ms / 切换 ASCII/UTF-8 都能回归
- **不破坏协议解析**: 协议解析独立路径
- **不破坏持久化**: 用户已有配置不受影响 (新装才走默认)
- **不破坏 modal**: 只动设备连接管理面板的 1 个 CSS 规则
