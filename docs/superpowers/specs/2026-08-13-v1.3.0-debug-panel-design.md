## 4. 关键设计决策

### 4.1 D1: 1 人多 tab 模拟（MVP），通信层 BroadcastChannel

**理由:** 用户实际场景是设备未到时 1 人多 tab 调试，不需要跨设备。

**实现:**
- BroadcastChannel 同源 API，0 部署
- 抽象成 `NS._debugTransport` 接口，未来换 WebRTC 只需替换 transport 实现
- 消息格式: `{ type, payload, ts }`，type 枚举: `cmd-frame | ack-frame | hello | bye | state-mutate`

**为什么不用 WebRTC P2P / WebSocket relay:** 跨设备需 signaling server 部署（云函数），不符合 v1.3 MVP 范围。

### 4.2 D2: UI 形态 = 折叠浮窗（现状延伸）

**理由:**
- 单 ⚙ 入口，符合"工具栏按钮越少越好"
- 0 占主区，不挤压卡片
- 现状延伸，改造低风险

**为什么不用右侧抽屉（B）/ 双入口（C）:**
- B 永久占 200px，挤压卡片
- C 2 个 UI 入口，违反"不喜欢散落多 modal"

**缓解 280px 紧:**
- 浮窗可调宽（280 → 360，拖右边）
- 浮窗可拖动（按 header 拖）
- Stats 段压缩（3 列 1 行）

### 4.3 D3: 4 段布局: Role / Channel / Mutator / Stats

**理由:**
- 跟 SerialCube 现有"段分割"设计语言一致
- 每段职责正交：身份 / 连接 / 行为 / 结果

**段排序理由:**
- Role 在最上：决定所有后续行为（注入路径 / 帧方向）
- Channel 第二：连接状态是 Mutator 能否生效的前提
- Mutator 第三：核心交互
- Stats 最后：观测结果

### 4.4 D4: Mutator 颗粒度 = 单条 + 预设 chip

**理由:**
- 单条满足"手动精确注入"（选 field + 设值 + 注入）
- 预设 chip 满足"一键演示"（过压 4.5V / 欠压 2.5V / 通信超时 / CRC 错）
- chip 列表从当前 active protocol dataFields 自动推，复用协议元数据

**为什么不用单条 + 持续注入（B）:** duration/interval 调试场景少，280px 装不下 3 行。
**为什么不用全做（D）:** 浮窗高度压力过大，需拉高 + 滚动，违反"信息密度合理"。

### 4.5 D5: 设备端内部 state 是 NS.currentVals 的同步副本

**理由:**
- 设备端引入独立 `NS._debugDeviceState` 对象，字段名跟 `NS.currentVals` 同步
- 设备端初始化时从 `NS.currentVals` 深拷贝，role 切换或协议切换时同步
- 注入路径: device role 改 `NS._debugDeviceState[field]`, 下次 ack 生成帧时**优先用 device state** (而不是 currentVals)

**为什么不直接复用 NS.currentVals:**
- currentVals 客户端用来触发告警, 改它会污染客户端状态
- 设备端需要独立的"假设备内部状态", 不能跟客户端的"解析后状态"混用
- 同步副本: 字段名一致, 但 device state 改值不影响 client 的 currentVals

**为什么引入独立对象而不是直接复用:**
- 解耦: client 改 currentVals (用于 UI 渲染 + 告警) ≠ device 改 state (用于生成下一帧)
- 测试性: device state 可单独断言, 不污染 currentVals

### 4.6 D6: ack 帧生成复用 NS.buildFrame（双向）

**理由:**
- `NS.buildFrame(proto, cmd)` 已是双向 API（send & respond）
- 设备端收到 cmd 帧后：解析 → 查 ack cmd → `buildFrame(proto, ackCmd)` → 返回

**复用 v1.2 现有 mock ack 模式:**
- v1.2 line 12719-12732: 30ms auto-ack 用 `NS.buildFrame(proto, ackCmd)`
- v1.3 设备端：把 `setTimeout 30ms` 换成"收到 BC 消息后立即生成"

## 5. 架构

### 5.1 通信层

```javascript
// NS._debugTransport 抽象接口
NS._debugTransport = {
  init(role) {},       // role: 'client' | 'device'
  send(msg) {},        // msg: { type, payload, ts }
  onReceive(cb) {},    // cb: (msg) => void
  close() {},
  isAvailable() {}     // 检测 BroadcastChannel 是否支持
};

// BC 实现
NS._debugBcTransport = {
  _bc: null,
  init(role) { this._bc = new BroadcastChannel('serialcube-debug-v1'); ... },
  send(msg) { this._bc.postMessage(msg); },
  onReceive(cb) { this._bc.onmessage = (e) => cb(e.data); },
  close() { this._bc?.close(); this._bc = null; },
  isAvailable() { return 'BroadcastChannel' in window; }
};
```

### 5.2 NS 状态（7 个新增）

```javascript
NS._debugChannel = null;            // BC instance (debug only, 跟 NS._debugTransport 配套)
NS._debugRole = null;               // 'client' | 'device' | null
NS._debugConnected = false;         // 收到首条 BC 消息后 true
NS._debugStats = { tx: 0, rx: 0, err: 0 };
NS._debugDeviceState = {};          // device role only, 字段名跟 NS.currentVals 同步, 改值不影响 currentVals
NS._crcOverride = null;             // CRC 错预设用, null=正常, 'force-bad'=下次生成 ack 帧时强制 CRC 错
NS._debugMutedUntil = 0;            // 通信超时预设用, 0=正常, >0=Unix ms 戳, 期间设备端丢弃所有 cmd
```

### 5.3 角色交互矩阵

| 动作 | 客户端 (client) | 设备端 (device) |
|------|---------------|---------------|
| 发命令帧 | NS._sendDebugCmd → BC.post(cmd-frame) | (不直接发) |
| 收命令帧 | (忽略，client 不处理 cmd) | BC.onmessage → 解析 → 查 ack cmd |
| 发 ack 帧 | (收 ack 后解析) | NS._buildDebugAck(cmd) → BC.post(ack-frame) |
| 收 ack 帧 | BC.onmessage → NS._triggerAckHandler | (device 不处理 ack) |
| Mutator 改 | `NS.currentVals[field] = value` → checkAlert | `NS._debugDeviceState[field] = value` → 下次 ack 用新值 |
| 预设 chip | 同 Mutator 改 | 同 Mutator 改 |

### 5.4 4 段 UI 详细规范

#### 段 1: Role (角色)
- 元素: Segmented button [客户端] [设备端]
- 高度: 28px
- 行为: 切换时关闭现有 BC，按新 role 重新初始化 + 广播 `hello`
- 状态: 默认 client（与现有"客户端"心智模型一致）

#### 段 2: Channel (通道)
- 元素: ● 状态点 + 通道名 + [启]/[停] 按钮
- 通道名: `BC:serialcube-debug-v1` (mono 字体 11px)
- 启停按钮: 28px 高，[启] 默认高亮（accent 蓝紫）
- peer 数: 收到首条消息后显示 `1 peer`

#### 段 3: Mutator (数据注入)
- **单条注入 (1 行, 38px 高):**
  - select field (flex 1.4, 22px 高, mono 字体)
  - input value (flex 1, 22px 高, mono 字体, 红色边框 = 校验失败)
  - [注入] 按钮 (28px 高, accent 色)
  - 字段从 active protocol `dataFields` 拉，按 field 名排序
- **预设场景 (1 行 flex wrap, gap 4px):**
  - 4-6 chip，从 `NS._presetScenariosFor(proto)` 推
  - chip: 22px 高, 11px 字号, var(--bg-elev) 背景, hover 变 accent
  - chip 数据结构: `{ label, field, value, description? }`

#### 段 4: Stats (统计)
- 元素: 3 列 grid [tx] [rx] [err]
- 每列: 数字 (mono, 12px) + 标签 (10px, var(--text-3))
- 实时更新: debounce 100ms，避免每帧 UI 重渲染
- err 颜色: >0 时变红（var(--danger)）

### 5.5 预设场景生成（核心算法）

```javascript
NS._presetScenariosFor = function (proto) {
  if (!proto) return [];
  const scenarios = [];
  const fields = (proto.commands || []).flatMap(c => c.dataFields || []);
  const numericFields = fields.filter(f => f.range && f.range.length === 2);
  if (!numericFields.length) return [];

  // 1. 过压: 取第一个 numeric field, value = range[1] + 10% margin
  const firstField = numericFields[0];
  const [min, max] = firstField.range;
  const margin = (max - min) * 0.1;
  scenarios.push({
    label: `过压 ${(max + margin).toFixed(1)}${firstField.unit || ''}`,
    field: firstField.name,
    value: max + margin,
    description: `推到 ${firstField.name} range 上限 +10%, 触发过压告警`
  });

  // 2. 欠压: 同一 field, value = range[0] - 10% margin
  scenarios.push({
    label: `欠压 ${(min - margin).toFixed(1)}${firstField.unit || ''}`,
    field: firstField.name,
    value: min - margin,
    description: `推到 ${firstField.name} range 下限 -10%, 触发欠压告警`
  });

  // 3. 通信超时: 设备端 5s 内不响应任何 cmd
  scenarios.push({
    label: '通信超时',
    type: 'mute',
    duration: 5000,
    description: '设备端 5s 内停止生成 ack, 模拟设备死机/通信中断'
  });

  // 4. CRC 错: 下次生成的 ack 帧强制 CRC 错误
  scenarios.push({
    label: 'CRC 错',
    type: 'crc-bad',
    description: '设备端下次 ack 帧生成时强制 CRC 错, 客户端解析应失败'
  });

  // 5-6. 范围边界值 (如适用): 选 range[0], range[1]
  if (scenarios.length < 6 && numericFields.length > 1) {
    const secondField = numericFields[1];
    scenarios.push({
      label: `${secondField.name}=${secondField.range[0]}`,
      field: secondField.name,
      value: secondField.range[0],
      description: `${secondField.name} 推到 range 下限`
    });
    if (scenarios.length < 6) {
      scenarios.push({
        label: `${secondField.name}=${secondField.range[1]}`,
        field: secondField.name,
        value: secondField.range[1],
        description: `${secondField.name} 推到 range 上限`
      });
    }
  }

  return scenarios.slice(0, 6); // 最多 6 chip
};

// 特殊类型 chip 处理
NS._applyDebugScenario = function (scenario) {
  if (scenario.type === 'mute') {
    NS._debugMutedUntil = Date.now() + scenario.duration;
    setTimeout(() => { NS._debugMutedUntil = 0; }, scenario.duration);
    return;
  }
  if (scenario.type === 'crc-bad') {
    NS._crcOverride = 'force-bad';
    return;
  }
  // 普通 chip: 走 Mutator 注入路径
  NS._injectMutation(scenario.field, scenario.value);
};
```

**注意:** `type: 'mute'` chip 只在 device role 生效; client role 显示但点击提示 "需在设备端触发"。

## 6. 数据流

### 6.1 命令帧 + ack 路径（client ↔ device）

```
Client tab                                       Device tab
─────────                                        ─────────
[NS._sendCmd 触发]                              
  ├─ frame = NS.buildFrame(proto, cmd)          
  ├─ NS._debugStats.tx++                        
  └─ NS._debugTransport.send({                   
       type: 'cmd-frame',                       
       payload: frame.bytes,                    
       ts: Date.now()                           
     })                                         
                                                 ↓
                                       [NS._debugTransport.onReceive]
                                         ├─ 若 NS._debugMutedUntil > Date.now() (mute 中), 丢弃
                                         ├─ 解析 payload (NS.parseFrame)
                                         ├─ 找 ack cmd (NS.allCommands())
                                         ├─ 临时: const _savedVals = { ...NS.currentVals }
                                         │       NS.currentVals = { ...NS._debugDeviceState }
                                         │       (buildFrame 用 currentVals 编码 dataFields)
                                         ├─ ack = NS.buildFrame(proto, ackCmd)
                                         ├─ NS.currentVals = _savedVals (立即还原, 不影响 client)
                                         ├─ 若 NS._crcOverride === 'force-bad', 改 ack.crc 字节
                                         ├─ NS._crcOverride = null (一次有效)
                                         ├─ NS._debugStats.tx++
                                         └─ NS._debugTransport.send({
                                              type: 'ack-frame',
                                              payload: ack.bytes,
                                              ts: Date.now()
                                            })
                                                 ↓
[NS._debugTransport.onReceive]
  ├─ NS._debugStats.rx++
  ├─ NS._triggerAckHandler(ackCmdId, ack.bytes)
  └─ 走现有 ack handler 流程（解析 + 渲染 + checkAlert）
```

### 6.2 Mutator 路径

```
Client tab:
[select field + input value + 点击注入]
  ├─ 校验: value 在 field.range 内 + 类型匹配
  ├─ NS.currentVals[field] = value
  ├─ NS.checkAlert()  // 触发告警检测
  └─ 渲染更新 (NS.renderKpiCards 走现有流程)

Device tab:
[select field + input value + 点击注入]
  ├─ 校验: 同上
  ├─ NS._debugDeviceState[field] = value
  └─ (不立即生效, 等下次 ack 帧生成时用新值)
```

### 6.3 预设 chip 路径

```
点击 chip '过压 4.5V'
  ├─ 从 chip 数据拿 { field: 'cell_1_v', value: 4.5 }
  ├─ 应用到 select + input (UI 同步)
  └─ 触发注入 (走 6.2 路径)
```

## 7. 错误处理

| 场景 | 处理 |
|------|------|
| BC 不可用（老浏览器） | `isAvailable()` 返回 false, 面板禁用, 显示 "浏览器不支持 BroadcastChannel" 提示 |
| 协议未选 | Mutator 段 field 下拉为空, [注入] 按钮 disabled, 提示 "请先选协议" |
| 字段值超范围 | input 红色边框 + tooltip "值超出范围 [min, max]", [注入] 按钮 disabled |
| 字段类型不匹配 | input 红色边框 + tooltip "类型应为 float/int", [注入] 按钮 disabled |
| 帧生成失败 | NS._debugStats.err++, toast 红色 "帧生成失败" |
| 设备端 timeout (1s) | 客户端 1s 后等不到 ack → 走现有 timeout (NS.txAckWaiters) |
| 角色切换时 BC 关闭中 | 关闭前发 `bye` 消息, 对方收到后状态变 "未连接" |
| 设备端收到非 cmd 帧 | 忽略, NS._debugStats.err++ |
