## 1. 背景 / 现有问题

v1.2 配置中心协议/命令/卡片删除用 `NS._cascadeConfirm()` 弹 browser confirm, 2 选项 (级联/取消). 用户实测反馈 3 个问题:

1. **UX 不一致**: 其他 modal (新建协议/命令/告警) 都是 SerialCube 自定义 modal 风格, 删除弹原生 confirm 不协调
2. **2 选项不灵活**: 没"仅删自己"选项, 用户删命令时想要保留引用卡片 (v1.2 line 13558 已经在做 `card.cmd = null`, 但 modal 路径没暴露)
3. **引用预览不友好**: 纯文本 "8 条命令 / 12 张卡片" 一行, 没分类, 没"会留孤儿"提示

告警删除 v1.2 也是简单 confirm, **v1.3.1 不升级** (跟 v1.3.1 backlog B "三选项级联 modal" 范围一致, 告警简单 confirm 已够).

## 2. 目标

1. 替换 3 个 `_cascadeConfirm` 调用点 (协议/命令/卡片) 为自定义 modal
2. 升级为 3 选项 (仅删自己 / 级联 / 取消)
3. 引用预览用 chip 分类 (彩色 chip 区分 cmd/card/alert)
4. "仅删自己" 按钮加 hint (说明会留 N 个孤儿)
5. 主题适配 (浅色 + 深色) 跟其他 modal 一致
6. 不破坏 v1.2 已发布功能 (旧 confirm 路径保留兼容)

## 3. 范围

### 3.1 In Scope (v1.3.1)

- 新建 modal: `dh-cascade-delete-modal` (X 右上 + title + meta + icon + body + 3 按钮 footer)
- 新建 `NS._openCascadeModal(type, id, label)` → 返回 'self' / 'cascade' / 'cancel'
- 替换 3 个 `_cascadeConfirm` 调用点 (line 14462 协议 / 14570 命令 / 14654 卡片)
- 引用预览 chip (彩色分类, 类型 + 计数)
- "仅删自己" hint (自动算孤儿数)
- 浅色 + 深色主题适配
- e2e 3 场景: 19-cascade-protocol-delete / 20-cascade-command-delete / 21-cascade-card-delete

### 3.2 Out of Scope (v1.3.2+ backlog)

- 告警删除升级为 3 选项 modal
- 协议/命令/卡片新建的"级联引用" 提示 (新建时显示被引用)
- modal 拖动 / 调整大小
- 撤销删除 (操作历史栈)
- 批量删除 (multi-select)

## 4. 关键设计决策

### 4.1 D1: 1 个统一 modal (按 type 参数化)

**理由:** 协议/命令/卡片 3 个场景 UI 完全一致 (title/meta 不同, 引用 chip 数量不同), 1 个 modal 足够. 避免 3 个 modal 维护成本.

**实现:**
- 1 个 HTML modal: `dh-cascade-delete-modal` (复用 `.modal-header-standard` 组件)
- `NS._openCascadeModal(type, id, label)` 按 type 调 `_findReferences` 拉引用
- 调用方传 type + id + label, modal 自适应显示

### 4.2 D2: 引用预览用简单计数 chip (不显示具体是谁)

**理由:** brainstorming 选 A. 80% 场景用户已知道删什么, 简单计数 modal 紧凑 (280px 装下), 实现简单. 完整明细 modal 高 (320px+), 用户实际很少看.

**实现:**
- 3 种 chip: `.ref-chip.cmd` (蓝紫) / `.ref-chip.card` (绿) / `.ref-chip.alert` (红)
- 每个 chip 显示 `<N> 条命令` / `<N> 张卡片` / `<N> 条告警`
- 0 引用时显示 "无引用对象" italic 文案
- 3 种 type 各自的 chip 集合: 协议 {cmd, card, alert} / 命令 {card, alert} / 卡片 {alert}

### 4.3 D3: 3 选项统一 (仅删自己 / 级联 / 取消)

**理由:** brainstorming 选 A. 一致性高, 用户自定决定. 仅删自己按钮加 hint 说明会留孤儿.

**实现:**
- 3 按钮: [取消] (ghost) / [仅删自己] (default) / [级联删除 (N 个)] (primary danger)
- 仅删自己 hint: "选'仅删自己'会留下 N 张孤儿卡片 + M 条孤儿告警, 引用悬挂" (动态算)
- 3 按钮顺序 (从左到右): 取消 → 仅删自己 → 级联删除 (危险操作放最右, 跟现有 modal 一致)

### 4.4 D4: 范围只升 3 个调用点 (协议/命令/卡片), 告警保留 confirm

**理由:** v1.3.1 backlog 选 B "三选项级联 modal" 范围明确, 告警简单 confirm 合理 (告警无引用概念). 一起升会增加 1 工作日.

**实现:**
- 替换 3 个 `_cascadeConfirm` 调用点
- 告警 line 14851 `confirm('确认删除告警...')` 保留不动
- 旧 `NS._cascadeConfirm` 函数保留 (兼容, 不删), 但不调用

## 5. 架构

### 5.1 modal 复用现有组件

- `.modal-header-standard` 复用 (X 右上 + title + 副标题) — v1.2.1 引入
- `.modal-backdrop` 复用 (v1.2.1 已修 z-index 1000+)
- 新增: `.cascade-modal-body` (引用预览 + 描述)
- 新增: `.ref-chip.cmd` / `.ref-chip.card` / `.ref-chip.alert` (彩色 chip)
- 新增: `.self-hint` (warn 背景 + 提示)
- 新增: `.modal-footer-3btns` (3 按钮区, 跟 v1.2.1 modal 一致)

### 5.2 NS 函数

```javascript
// 新增
NS._openCascadeModal = function (type, id, label) {
  // 1. 拉引用
  const refs = NS._findReferences(type, id);
  // 2. 算仅删自己孤儿数
  const orphanCount = (refs.commands?.length || 0) + (refs.cards?.length || 0) + (refs.alerts?.length || 0);
  // 3. 渲染 modal
  NS._renderCascadeModal(type, label, refs, orphanCount);
  // 4. 打开 modal, 返回 Promise
  return new Promise((resolve) => {
    NS._cascadeResolve = resolve;
    NS.openModal('dh-cascade-delete');
  });
};

// 保留兼容 (不删, 不调用)
NS._cascadeConfirm = function (type, id, label) { /* v1.2 简化 confirm */ };
```

### 5.3 调用方适配

```javascript
// 旧 (v1.2):
const result = NS._cascadeConfirm('protocol', delId, '协议 ' + delId);
if (result === 'cancel') return;
// ... 删协议逻辑 (line 14460-14484)

// 新 (v1.3.1):
const result = await NS._openCascadeModal('protocol', delId, '协议 ' + delId);
if (result === 'cancel') return;
// ... 删协议逻辑 (同 v1.2)
```

3 个调用点同步改: line 14462 / 14570 / 14654.

## 6. 数据流

### 6.1 删除协议流程 (以协议为例)

```
User 点 [删除] 按钮 (line 14461)
  ↓
NS._openCascadeModal('protocol', delId, label) [NS 新函数, v1.3.1]
  ├─ _findReferences('protocol', delId) → { commands: 8, cards: 12, alerts: 4 }
  ├─ orphanCount = 8 + 12 + 4 = 24
  ├─ _renderCascadeModal(...) → 渲染 modal
  ├─ openModal('dh-cascade-delete') → 浮起
  └─ return Promise (resolve 在 3 按钮 click 时触发)
       ↓
User 点 [取消] → resolve('cancel') → 不删
User 点 [仅删自己] → resolve('self') → 删自己, 不动引用 (v1.2 现有代码保留)
User 点 [级联删除] → resolve('cascade') → 删自己 + 引用方 (v1.2 现有代码保留)
```

### 6.2 modal 状态

- 默认: [取消] 按钮聚焦 (键盘 Enter = 取消, 安全)
- 背景点击 = [取消]
- Esc = [取消]
- 仅删自己 hint: 实时显示, 算 orphanCount = (ref counts)

## 7. 错误处理

| 场景 | 处理 |
|------|------|
| `_findReferences` 返回空 (0 引用) | modal 显示 "无引用对象", [仅删自己] = [级联删除] (效果一样, 但用户可选 1 个) |
| 删除时数据竞争 (用户并行编辑) | 走 v1.2 现有逻辑, 没特殊处理 |
| `openModal` 失败 (modal 已被开) | 走 v1.2 现有 `NS.openModal` 错误处理 |
| promise 没 resolve (modal 被外部关) | 用 finally 兜底, 默认 resolve('cancel') |

## 14. 用户偏好遵守 (来自 memory)

- ✅ **数据字段归命令不归协议** (引用 chip 按 cmd/card/alert 分类)
- ✅ **图标只用 inline SVG** (warn 三角 icon + trash icon)
- ✅ **工具栏按钮越少越好** (1 个 modal 入口, 不破坏工具栏)
- ✅ **正交分层一站式 modal** (复用 .modal-header-standard, 跟其他 modal 一致)
- ✅ **modal 不用内嵌表单** (3 按钮清晰分区, 不嵌套)
- ✅ **3 步向导 > 1 步长表单** (modal 内部 3 段: 引用预览 + 描述 + 3 按钮)
- ✅ **modal-review 6 步 guard** (新建 modal 必跑, spec §5.1 走)
- ✅ **agent-browser 验证** (改完 3 e2e 场景 + 浅/深主题截图)
