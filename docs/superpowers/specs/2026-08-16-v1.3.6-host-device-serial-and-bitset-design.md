# SerialCube v1.3.6 仪表盘主从机真串口调试 + 位字段解析 — 设计 Spec

> **状态**: 设计完成，待实施

## 1. 背景 / 现状问题

1. **调试面板无用**: 仪表盘右下角 BroadcastChannel 调试面板（v1.3.0）是浏览器内多 tab 假模拟（不经真串口），无实际调试价值，占位需移除。
2. **卡片无法解析位字段**: 卡片字段选择器只读 `cmd.dataFields`（schema 协议命令 `dataFields: []`），导致 BMS V1.13 / EMS 的字段无法配卡；且 BMS 的 `ProtectCode/ErrCode/AFE_ProtectCode/ChgDsgState/CellBalance` 是 bitset 却无 `bits[]` 位定义，位未展开。
3. **BMS V1.13 配置不完整**: `bms_v113.json` 仅 0x01/0x02/0x03 完整，0x04-0x16 为 todo 骨架；注册命令仅 3 条。
4. **无主机/从机真串口互调**: 页面无法以主机身份轮询下发命令、以从机身份按规律响应，无法用两个串口直接互调。

## 2. 目标

1. 移除 BroadcastChannel 调试面板（HTML/JS/CSS 全清）
2. 卡片可解析并展示数据字段的**任意一位**（如 BMS 电池常规保护 uint16 的 16 个保护位）
3. 内置**完整 BMS V1.13**（19 命令全字段）导入配置
4. **双 tab 真串口互调**: host tab（连串口 A，轮询下发可配）+ device tab（连串口 B，响应数据源可配），经虚拟串口对互调；同样覆盖「主机连真设备」「从机被真上位机连」场景

## 3. 范围

### In Scope
- A: 移除调试面板（HTML 段 / NS._debug* 函数 / 绑定 / CSS）
- B: 位字段解析（bitset bits[] 补全 + 卡片字段选择器扩展 + 位字段告警）
- C: BMS 完整配置（0x04-0x16 字段表 + 19 命令注册 + 导入导出兼容）
- D: 双 tab 主机/从机真串口互调（角色模式 + 主机轮询配置卡 + 从机数据源配置卡）

### Out of Scope
- 单页面双串口（D2，用户已选 D1 双 tab）
- WebRTC/跨设备联调（继续留 hook，本版不做）
- 从机复杂业务逻辑模拟（仅数据源：固定/随机/正弦/斜坡）

## 4. 关键设计决策

### 4.1 A: 调试面板移除
- 删除 `#dh-debug-panel` HTML、`NS._debugChannel/_debugRole/_debugBcTransport/_onDebugReceive/_switchDebugRole/_sendDebugCmd/_recvDebugFrame/_injectMutation/_presetScenariosFor/_renderDebugPresets/_applyDebugScenario` 及绑定。
- **保留** `NS._serialConnected` 同步、`NS._writeSerial` 写串口回调（D 复用）。
- 删除 `.debug-panel/.debug-toggle/.debug-body` 等 CSS。

### 4.2 B: 位字段解析
- **位定义来源**: `docs/reference/bms通讯协议V1.13.xlsx` 的「BMS保护标志位」sheet（逐 bit C 变量名），用脚本解析 → 写入 `bms_v113.json` 的 `bits[]`（复用 `tools/scripts/parse-ems-dump.py` 套路）。
- **位展开键**: `parseFrame` 已支持 bitset → `字段名.位名`（如 `ProtectCode.Bit0_软件层放电过温`），无需改解析。
- **卡片字段选择器扩展**: schema 协议命令的字段下拉从 `protocol.schema.commands[cmd].REQ/RESP.fields` 枚举，bitset 字段展开 `字段名.位名` 选项；卡片 `field` 可配到位。
- **渲染**: `renderCard` 取 `currentVals[field]`（0/1），位字段 range 默认 `[0,1]`；告警支持「位=1 触发」。

### 4.3 C: BMS 完整配置
- 解析 `docs/reference/BMS通信协议V1.13.md`（1352 行，19 命令）命令表格 → 补全 `bms_v113.json` 0x04-0x16 字段表。
- `NS._registerSchemaProtocols` 注册 19 命令（frameType/cadence/schemaDir）。
- 导入导出 JSON 兼容完整 schema 格式。

### 4.4 D: 双 tab 主机/从机真串口互调（D1）
- **角色模式**: dashboard 增加 `NS._simRole = 'host' | 'device'`（默认可在仪表盘顶部切换）。
- **主机 host**: 连串口 A → 按命令 `cadence` 轮询发查询帧（复用 `_buildFrameSchema` + `_writeSerial`）；**配置卡**：轮询间隔覆盖、启用/停用命令、手动下发。
- **从机 device**: 连串口 B → `tryDispatchSchemaFrames` 收到查询 → 按 schema 响应布局回帧（复用 `_buildFrameSchema` 的 RESP 方向 + `_writeSerial`）；**数据源配置卡**：每个响应字段可选「固定值 / 随机[lo,hi] / 正弦(基频+振幅) / 斜坡(步进)」。
- **互调**: 两 tab 分别连虚拟串口对（com0com/Eltima）的 COM_A / COM_B。
- 复用 P2 已实现的 `tools/schema_codec.py` 与 `device_sim.py` 逻辑作为页面内 JS 参照。

## 5. 分阶段任务

| 阶段 | 内容 | 估时 | 验证标志 |
|------|------|------|---------|
| **A** | 移除调试面板 | 0.5 天 | 页面加载无报错、仪表盘无调试面板；L1/smoke 全绿 |
| **B** | 位字段解析 | 1 天 | bms_v113.json 保护标志位 bits[] 齐全；卡片可配位字段；L1 新增位展开断言 |
| **C** | BMS 完整 19 命令 | 1-2 天 | bms_v113.json 0x04-0x16 字段表补全；19 命令注册；L1 schema 校验全绿 |
| **D** | 双 tab 主机/从机 | 2-4 天 | host tab 轮询发帧 + device tab 规律响应，经虚拟串口对互调通；e2e/手工验证 |

## 6. 验证

- 每个阶段：L1（`node tests/protocol.test.mjs`）+ L2（`python tests/test_sim.py`）+ smoke（`node .tmp/smoke.mjs`）+ token/版本/链接门禁全绿。
- D 阶段：本环境无真实串口/浏览器，以单元级（host 轮询引擎发帧正确性、device 响应引擎按数据源生成正确性）+ socket 回环集成测试覆盖；真串口互调由用户在 Chrome + 虚拟串口对实测。

## 7. 风险

| 风险 | 对策 |
|------|------|
| 移除调试面板牵连 `_serialConnected/_writeSerial` | 保留这两个，仅删 BroadcastChannel 相关 |
| BMS xlsx「BMS保护标志位」sheet 解析格式未知 | 先 dump 该 sheet 内容再写解析（同 EMS 套路） |
| 卡片字段选择器大改影响既有卡片配置 | 仅扩展下拉数据源，不改 card 结构；旧配置兼容 |
| 从机数据源配置复杂度 | 先用「固定/随机/正弦/斜坡」四种，卡片级配置，不引入脚本引擎 |
| 单文件体积膨胀（完整 schema） | bms schema 补全后 re-embed，监控体积；必要时 schema 惰性加载 |
