## 2. 目标

1. 一次性解决 8 个 UI/UX 问题
2. 统一所有 modal 的 header 规范（后续 modal 默认遵守）
3. 协议编辑 modal 职责正交：管理"协议本身"（schema 层），命令编辑 modal 仍管"单条命令"（instance 层）
4. 不破坏 v1.2 已发布功能，所有改动向后兼容（导入旧配置不报错）
5. 主题适配（浅色 + 深色）保持现有 `var(--bg) / var(--bg-terminal) / var(--text)` 规范
6. v1.3 真实模拟调试面板继续保留为后续 phase（v1.3.0），本次**不实施**

## 4. 关键设计决策

### 4.1 A1: 仪表盘"设置值/字节预览"挪到 modal

**理由：** 未连接串口时（占 80% 调试初期），下方"设置值/字节预览"区域是空内容，常驻只占空间。这个区域是"已连接后填值用"的辅助，挪到 modal 不影响主流程。

**实现：**
- 工具栏"选择协议"按钮**旁边**新增"⚙ 设置值"按钮（点开 modal）
- 移除 `#dash-area` 底部"设置值/字节预览"常驻区
- 复用现有 `buildFrame()` + `.frame-preview` 组件，容器 id 改 `#dash-frame-preview-modal`
- 打开条件：已连接 + 已选协议（否则按钮 disabled）

**为什么不用方案 A2（折叠 bottom panel）/ A3（sidebar）：**
- A2 多一个折叠状态要记，违反"工具栏按钮越少越好"原则
- A3 永久占 280px 宽，小屏（1280×800）不可用
- A1 modal 化最干净，符合"工具栏按钮 + 正交 modal"模式

### 4.2 A2: 协议条"引导"按钮删除

**理由：** 用户反馈"没什么用"，从 v1.2 部署后没被触发过一次。

**实现：** 直接删除 DOM 节点，0 行新增代码。

### 4.3 B2: 统一 `.modal-header` 组件（4 个 modal 一次对齐）

**理由：** 当前 4 个 modal 各自写 header，X 位置 / title 位置 / 面包屑都不一致。建一个共享组件后，后续 modal 默认遵守。

**实现：**
- 新增 CSS class `.modal-header-standard`：
  ```css
  .modal-header-standard {
    display: flex; align-items: center;
    padding: 16px 20px;
    border-bottom: 1px solid var(--border);
  }
  .modal-header-standard .title-block .title { font-weight: 600; font-size: 16px; }
  .modal-header-standard .title-block .subtitle { color: var(--text-soft); font-size: 12px; margin-top: 2px; }
  .modal-header-standard .close-btn { margin-left: auto; ... }
  ```
- 4 个 modal 改用 `<div class="modal-header-standard">` 替换各自 header
- 关闭 X 按钮用 `var(--text-soft)` 色，hover 变 `var(--text)`
- 影响的 modal：`openSelectProtocolModal` → 合并到 4.5 解决；`openNewCommandModal` / `openAlertEdit` / 合并后的"协议配置 modal" / 合并后的"协议编辑 modal"（共 4 个：协议配置 + 协议编辑 + 命令编辑 + 告警编辑）

**为什么不用方案 B1（仅挪 X）：**
- B1 解决症状不解决根因，下次加 modal 又会忘

**为什么不用方案 B3（完全重做 modal）：**
- YAGNI，当前 modal 尺寸够用，重做 scope 爆炸；推迟到 v2.0 设计系统重构

### 4.4 C3+: 协议编辑 modal 改 1 步长表单（4 段）

**理由：** v1.2.0 协议编辑 modal 渲染的是"单条命令配置"（重复了命令编辑 modal 职责），逻辑错位。协议应该是 schema 层（多字段 + 多命令 + 帧格式），不是 instance 层（单条命令）。

**实现：**
- 4 段布局（用户改主意 C3→C3+）：
  1. **① 基础** — 显示名 / 内部 ID / 类型 / 标签（4 个字段 grid）
  2. **② 帧预览** — 复用现有 `renderFramePreview()` 渲染 byte 序列（带 7 种类型色块 + 标注每个段）
  3. **③ 帧字段** — 字段表（name / type / len / endian / default）
  4. **④ 命令列表** — 命令表（ID / name / dir / payload fields / 操作）
- 顶部 dropdown 切换要预览哪个命令的 payload（默认第 1 个）
- 改任一字段 / 命令 → 帧预览实时重算
- 复用 `#dh-new-cmd-frame-preview` 现有渲染函数（line 7848-7856）+ `.frame-bytes .byte.{type}` 7 种色块（line 6707-6722）

**关键 CSS 复用（不引入新样式）：**
```css
.frame-bytes .byte.header { background: rgba(129, 140, 248, 0.18); color: var(--c-header); }
.frame-bytes .byte.cmd { background: rgba(217, 119, 6, 0.18); color: var(--c-cmd); }
.frame-bytes .byte.length { background: rgba(34, 197, 94, 0.18); color: var(--c-length); }
.frame-bytes .byte.data { background: var(--bg); color: var(--c-data); }  /* 关键: 微差"切开"感 */
.frame-bytes .byte.crc { background: rgba(224, 87, 94, 0.18); color: var(--c-crc); }
.frame-bytes .byte.tail { background: rgba(129, 140, 248, 0.18); color: var(--c-tail); }
```

**关键:** `.byte.data { background: var(--bg) }` 而**不是** `var(--bg-terminal)` —— 故意让 data 段跟 frame 容器（`var(--bg-terminal)`）有微差"切开"感。这是 SerialCube 原始设计意图（line 6720）。

**为什么不用方案 C1（3 Tab）：**
- C1 实现重（3 个 tab 状态机 + 切换动画 + 缓存），modal 内 Tab 切换不直接

**为什么不用方案 C2（3 步 wizard）：**
- 编辑场景过重，改了第 1 步想看第 3 步要回到第 1 步点下一步

### 4.5 D1: 合并"选择协议 modal"和"协议配置 modal"为 1 个

**理由：** 独立"选择协议 modal"只做"3 选 1 + 记住选择"，认知负担高（啥时候用哪个？）。直接让用户在协议配置列表里点"应用"按钮即可。

**实现：**
- 仪表盘顶部"选择协议"按钮**直接打开"协议配置 modal"**（与系统菜单 → 配置中心 → 协议 tab 走同一 modal）
- 协议配置 modal 的协议列表每行加"应用"列：
  ```
  | ● 应用 | 状态 | 显示名 | 类型 | 字段 | 命令 | CRC | 操作 |
  |  ●    | 使用中 | BMS TLV v1 | fixed-header | 7 | 8 | crc16-modbus | ✎ ⎘ 🗑 |
  |  ○    | 未使用 | Modbus RTU | fixed-header | 7 | 0 | crc16-modbus | ✎ ⎘ 🗑 |
  ```
- 点 ○ / ● 即时切换 `NS.activeProtoId` + 重渲染仪表盘
- 删除独立的 `openSelectProtocolModal()` 函数（约 30 行可删）
- 删除"选择协议"独立 modal 的 DOM / CSS

**为什么不用方案 D2（保留独立 modal）：**
- 多一个入口 = 多一个心智模型，认知负担

**为什么不用方案 D3（被动选择）：**
- 跨协议调试时容易选错，YAGNI

### 4.6 D6: 协议配置 modal 内"新建协议"按钮去重

**理由：** 同一按钮 3 处入口，用户分不清"哪个是真的"，违反"工具栏按钮越少越好"。

**实现：**
- 删除顶部 header 右上"新建协议"按钮
- 删除底部 footer"完成"按钮旁的"新建协议"按钮（如果有）
- 只保留内容区右上"新建协议"按钮（离协议列表最近，最自然）

## 8. 错误处理

| 场景 | 处理 |
|------|------|
| 用户在协议配置 modal 切换应用时无活动串口 | 允许切换（`NS.activeProtoId` 改为新值），但仪表盘仍显示"未连接串口"占位，激活协议在连接后自动应用 |
| 删除协议后该协议的"应用"切换失败 | 协议删除时级联清空 `NS.activeProtoId`（如果指向被删协议），仪表盘降级到"未选协议"占位 |
| 帧预览 dropdown 切换命令时该命令被删 | 切回 dropdown 第 1 个有效命令；如果是空数组，显示"—"占位 |
| 帧预览实时重算时 buildFrame() 抛错 | 显示"—"占位 + 1.5s 红框（沿用 v1.2 错误样式） |
| 导入旧 v1.2 配置后协议应用状态丢失 | `NS.activeProtoId` 默认 `null`（已有），用户首次打开手动选 |

## 10. 风险 + 后续

| 风险 | 缓解 |
