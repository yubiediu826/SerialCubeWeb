## 1. 背景 / 现有问题

用户在调试 SerialCube 配置中心时反馈 5 个 UI/逻辑自洽性问题，全部对应到 `SerialCube.html` 具体代码位置：

| # | 问题 | 代码位置 | 根因 |
|---|------|---------|------|
| 1 | 协议编辑器"只有完成可点"——分不清"应用/取消" | `SerialCube.html:12946-12952` + `dh-proto` modal | 编辑按钮直接改 `NS.activeProtoId` + 打开 modal，"完成"=直接保存，没有对比/取消，"应用"概念缺失 |
| 2 | 命令无法编辑——只能新建/删除 | `SerialCube.html:13022-13034` (Tab 2) + `openNewCommandModal` 行 12800 | `openNewCommandModal` 硬编码"新建"流程，没有"传现有 cmd"模式 |
| 3 | 卡片新建"命令不可选" + 告警"无法编辑" | `SerialCube.html:13086-13093` + `openCardEdit` 行 12358 + `openAlertAdd` 行 13165 (TBD toast) | 卡片新建用 `allCmds[0]` 默认 cmd，cmd 下拉没按协议分组；告警"手动添加"是 toast 占位 |
| 4 | 告警严重度全硬编码 warn | `SerialCube.html:13132` | 告警只能从卡片 range 派生，没有独立规则存储 |
| 5 | 协议 select 切换无"应用"按钮 | `SerialCube.html:12903-12907` | 协议切换只改 local state，仪表盘/卡片不受影响，没有"激活协议"概念 |

**用户二次反馈（关键修正）：**"串口不是只能一对一吗？仪表盘为啥要显示多种协议？" —— 串口 1 对 1 的物理事实让原方案 C（多协议并行）不合理。修正为方案 D（单协议聚焦）。

---

## 2. 目标

1. 一次性解决上述 5 个 UI/逻辑问题
2. 引入"激活协议"概念，跟随串口连接状态自动绑定
3. 告警从派生模式改为独立规则模式（NS.ALERTS）
4. 命令编辑支持新建/编辑/复制三模式复用
5. 真实模拟（v1.3）—— **不在本次范围**，但预留"调试"面板占位
6. 改完接用户环境（虚拟串口 COM20/COM21）跑集成验证

## 4. 关键设计决策

### 4.1 方案 D：单协议聚焦 + 串口绑定

**理由：** 串口 1 对 1，物理上不可能同时调试多协议。仪表盘只显示"当前正在调试"那个协议的卡片，UI 更干净，工具栏更少。

**实现：**
- `NS.activeProtoId` 全局变量，跟随连接状态
- 串口连接时弹"选择协议"小框（用户手动选 3 选 1）
- 仪表盘只渲染 `card.protocol === NS.activeProtoId` 的卡片
- 未连接时显示"未连接串口"占位 + "选择串口"按钮
- 已连接时显示"协议条"（当前协议 + 串口信息 + 切换协议按钮）

### 4.2 命令编辑 modal 三模式复用

**API：** `NS.openNewCommandModal(protocolId, editCmd?)`

| 模式 | editCmd 参数 | 标题 | 底部按钮 |
|------|--------------|------|----------|
| 新建 | `null` | "新建命令" | 取消 / 保存 |
| 编辑 | cmd 对象 | "编辑命令" | 取消 / 保存修改 |
| 复制 | 浅拷贝 + 新 ID | "复制命令" | 取消 / 另存为副本 |

### 4.3 告警独立规则

**数据结构：** `NS.ALERTS = []`

```js
{
  id: 'alert_<timestamp>',
  enabled: true,
  name: 'Cell 过压',
  protocol: 'proto_bms',        // 协议 ID
  cmd: 0x01,                     // 命令 ID (int)
  field: 'cell_1_v',             // 字段名
  op: '>',                       // 触发条件: > < = != range rate
  value: 4.2,                    // 比较值 1
  value2: null,                  // 范围比较时填 (range 模式)
  severity: 'danger',            // info / warn / danger
  notify: ['toast', 'list'],     // toast / sound / list
  debounceMs: 2000,              // 防抖间隔
  createdAt: '2026-08-10',
  updatedAt: '2026-08-10'
}
```

**"从卡片重建"按钮：** 扫描所有 `card.range`（`[min, max]`）自动生成默认规则（warn 严重度），不覆盖已存在的同名规则。

### 4.4 删除级联策略

**原则：拒绝直接级联，列出引用让用户决策。**

| 实体 | 被引用方 | 删除行为 |
|------|----------|----------|
| 协议 | 命令 / 卡片 / 告警 | 弹 confirm "N 条命令 / N 张卡片 / N 条告警将一起删除" + 三个选项：仅删协议（级联）/ 取消 |
| 命令 | 卡片 / 告警 | 弹 confirm "N 张卡片 / N 条告警将一起删除" + 三个选项：仅删 cmd（级联）/ 取消 |
| 卡片 | 告警 | 弹 confirm "N 条告警将一起删除" + 三个选项：仅删 card（级联）/ 取消 |
| 告警 | — | 直接删除，无引用 |

### 4.5 v1.3 调试面板占位

**位置：** 仪表盘右下角浮动按钮（默认折叠，仅显示 ⚙ 图标）

**v1.2 实现：**
- 浮动按钮 + 折叠面板 HTML 骨架
- 面板标题 "调试面板 (v1.3)" + 灰字说明
- 2 个占位区块："主从连接 (BroadcastChannel)" / "数据注入 (Mutator)"，各显示 "v1.3 待实现" 提示
- 不连接任何功能，纯占位

**v1.3 实现：**
- 主从连接：tab id + BroadcastChannel 心跳 + 连接状态
- 数据注入：字段下拉 + 强制设值 + 触发告警 + 重置

### 4.6 主题适配原则 (v1.2 整体要求)

**v1.2 所有新加/改动的 UI 必须支持浅色 + 深色主题，跟随 `prefers-color-scheme`。**

**规则：**
- ❌ 禁止硬编码颜色（如 `#0d1117` `#79c0ff` 等）— 必须用 CSS 变量
- ✅ 背景用 `var(--bg-elevated)` / `var(--bg-panel)` / `var(--bg-subtle)` / `var(--bg-terminal)`
- ✅ 文字用 `var(--text)` / `var(--text-soft)`
- ✅ 边框用 `var(--border)` / `var(--border-strong)`
- ✅ 分类色块用 `var(--accent)` / `var(--success)` / `var(--warning)` / `var(--danger)` / `var(--signal)`
- ✅ 用户手动主题切换（`theme-light` / `theme-dark` class）也要支持（参考 SerialCube.html 行 198+ 的 `:root.theme-dark` 块）
- ✅ 帧预览（命令编辑 modal）等"终端"风格区块用 `var(--bg-terminal)` 自动切换

**验证：**
- macOS 系统设置切换暗色 → 整个 v1.2 UI 自动跟随
- SerialCube.html 顶部主题切换按钮 → 也能切

## 5. 数据结构变化

### 5.1 新增字段

| 字段 | 实体 | 默认 | 用途 |
|------|------|------|------|
| `protocol` | `CARDS[i]` | `'proto_bms'` | 卡片归属协议，用于单协议过滤 |
| `activeProtoId` | `NS` (全局) | `null` (未连接) | 当前激活协议 ID |

### 5.2 新增全局变量

| 变量 | 类型 | 初始值 | 用途 |
|------|------|--------|------|
| `NS.ALERTS` | Array | `[]` | 告警规则独立存储（从卡片 range 派生改为独立） |
| `NS.activeProtoId` | String\|null | `null` | 当前激活协议 ID |
| `NS._pendingConnectPort` | SerialPort | `null` | 串口连接后等待选协议的中间态 |
| `NS._debugPanelCollapsed` | Boolean | `true` | 调试面板折叠状态 |

### 5.3 兼容性处理

- 导入 v1/v2 配置时：自动给缺 `protocol` 字段的 card 补 `'proto_bms'`（v1 import 已实现，见 `SerialCube.html:12461`）
- 升级时自动生成默认告警：扫描所有 `card.range`，每张生成 1 条 warn 规则

## 8. 错误处理

| 场景 | 处理 |
|------|------|
| 串口连接失败 | 保留原 connectBtn 错误提示（红/黄高亮） |
| 串口连接成功但用户取消选协议 | 断开串口（rollback），不进入活跃状态 |
| 删除协议/命令时有未处理引用 | 弹 confirm 列出引用，用户选"仅删自己"或"级联删"或"取消" |
| 告警引用的 cmd/field 不存在 | 告警编辑 modal 顶部显示警告，保存时弹 confirm |
| 导入配置时 protocol 字段缺失 | 旧 card 强制补 `'proto_bms'`，v2 import 已有 fallback |
| Mock 数据初始化时无 activeProtoId | 仪表盘显示"未连接串口"占位，不进入 tick 循环 |
| `bump-version.ps1` 检测到 VERSION 与代码不同步 | R1 规则阻塞 commit |
