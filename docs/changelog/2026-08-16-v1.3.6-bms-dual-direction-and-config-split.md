# v1.3.6 — BMS 双向解析 + 新建卡片下拉修复 + 主机/从机配置拆分

**VERSION**: 1.3.5 → 1.3.6
**日期**: 2026-08-16
**类型**: bug fix + 配置架构

## 背景

用户实测报 3 个问题：

1. **协议解析严重问题** — 命令 0x01 是双向的：主机侧发控制字段（MB，2 字节 ctrl 位表），从机侧回遥测（CB，159 字节，48 字段）。需要正确支持 MB/CB 双方向。
2. **新建卡片编辑界面不支持命令/字段选择** — 下拉框看着是空的，无法选命令和字段。
3. **仅有一个 bms_v113.json，缺主机和从机单独配置文件，且配置内容不完整** — 需要支持协议全部命令和字段解析。

## 根因与修复

### P1 — 0x01 双向解析

- 帧方向靠帧头 `0x5A`(MB) / `0x55`(CB) 判向，链路本身正确；但存在两个掩盖性缺陷：
  - 0x01 MB 黄金向量陈旧（1 字节 `len=01`），而文档 §4.1 权威定义是 2 字节 → 归一为 2 字节并重算 CRC（`5A 01 01 02 00 00 91 1D` / `5A 01 01 02 01 00 90 8D`）。
  - CB 帧 len 字段语义混乱：文档示例帧写 `len=0x8F(143)` 但位表实到 159 字节 → 统一以位表 159B 为权威，`_buildFrameSchema` 组帧写 `len=0x9F`，schema note 标注文档异常。
- 新增 2 个 L1 测试：MB 帧头/len/ctrl 位往返 + 主机发 MB → 从机回 CB → 主机按 CB 解析遥测（含 RFCC/AFCC 尾部字段与 ProtectCode 位）。

### P2 — 新建卡片下拉空白

- 根因：`#dh-ce-cmd` / `#dh-ce-field` 在应用初始化时被 `syncCustomSelects` 包成 custom-select，此时 options 为空 → 浮动菜单被建成空。`openCardEdit` 之后用 `innerHTML` 填入真实 options，但旧的本地 `syncCustomSelectLabel` 只更新 trigger 上的 label 文字，**没有重建浮动菜单的选项按钮**。
- 修复：`openCardEdit` 填充 options 后调用完整重建 `syncCustomSelects(modal)`（含浮动菜单 options 重建）；命令切换 `onchange` 重填字段后同样重建。
- 新增 L1 测试：断言 `#dh-ce-cmd` options ≥ 19、`#dh-ce-field` options ≥ 50、浮动菜单 `.custom-select-option` 数量 ≥ 19、字段菜单含位展开项。

### P3 — 主机/从机配置拆分 + 补全

- **拆分**：`tools/schemas/bms_v113_host.json`（MB 布局，18 命令）+ `tools/schemas/bms_v113_slave.json`（CB 布局，19 命令）。0x15（升级完成状态）为 CB-only 主动上行，仅存在于 slave 侧。
- **合并**：新增 `tools/scripts/merge-bms-schema.mjs`，运行时把 host/slave 合并为单一 `bms_v113.json`（判向需同一 schema 内同时有 MB+CB）；`embed-schema.mjs` 自动先 merge 再嵌入。
- **补全**：
  - `0x16` MB：原 `len:0`（reserved bytes）→ `len:4`（reserved u32），golden 帧 `5A 01 16 04 00 00 00 00 26 BE`。
  - `0x14` MB：原 `PAC bytes + todo` → `PAC_NUM u16` + `PAC array[u8 × 128]`，`len:130`，支持变长升级数据包编解码往返。
- **方向标注**：卡片字段下拉把字段按方向标注 `[MB]` / `[CB]`，控制字段与遥测字段不再混排。

### P3.1 — schema 文件导入支持（修复「导入 host/slave 失败」）

- 根因：导入/导出 tab 的 `importConfig` 只接受 `type: SerialWebUserConfig` 用户配置，schema 文件（有 `frame.fields` + `commands`，无该 type）被拒 → 提示「type 不是 SerialWebUserConfig」。
- 修复：`importConfig` 检测到 schema 结构后转交新增的 `NS.importSchema`：
  - 归一 id（`proto_bms_v113_host/_slave` → `proto_bms_v113`），同 id 的 schema 协议合并布局；
  - host(MB) 与 slave(CB) 拆分文件依次导入自动合并为双向协议；
  - 完整 schema（合并产物）也可直接导入；
  - 单侧导入给出提示「建议再导入另一侧 host/slave 文件」；
  - 导入后自动持久化 + 重渲染。
