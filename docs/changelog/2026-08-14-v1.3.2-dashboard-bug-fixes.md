## v1.3.2 · 2026-08-14

**主题:** 仪表盘 3 个阻断 bug 修复 · 命令 panel 过滤 · 选择串口 binding · 应用协议渲染

### 背景

用户实测报告 3 个阻断性 bug, 仪表盘"应用协议"流程完全不可用:

1. **默认进去命令 tab 就有数据** — `renderCommandPanel` 用 `NS.allCommands()` 跨协议 flatMap, 不过滤 `activeProtoId`, 默认 `null` 时显示所有协议命令 (BMS 8 条)
2. **应用协议后界面消失, 选择串口按钮无效** — `dh-dash-choose-port` 按钮 (HTML line 8106) 无任何 click handler, `updateDashboardProtoBar` 只看 `activeProtoId` 不看串口是否连
3. **协议切换不刷新** — 跟 bug 1 同根因 (命令 panel 不过滤), `renderAlerts` 也不过滤; `dh-proto-apply` 按钮只 toast + 关闭 modal, 没调任何 render

附加发现: `NS.serialConnected` 在 NS 命名空间里从未被赋值 (line 14344, 14352 引用但定义找不到), 导致 `updateDashboardSettingsBtn` 永远 disabled, `openDashboardSettingsModal` 永远弹 alert。

### 改动点 (按代码行号)

1. **renderCommandPanel 按 activeProtoId 过滤** (line 11322-11410) — `!activeProtoId` 时整个 panel 不显示任何 chip (跟 `renderCardGrid` line 11607 一致), `activeProtoId` 有值时直接遍历 `NS.PROTOCOLS[i].commands` (因为 cmd 对象没 own protocol 字段, `allCommands()` flatMap 后丢失协议关联)
2. **renderAlerts 按 activeProtoId 过滤** (line 11693-11719) — 改 `const cardsToCheck = (NS.CARDS || []).filter(...)` 跟 `renderCardGrid` 一致
3. **dh-dash-choose-port 绑 click handler** (attachModalHandlers) — 转发到主应用 `document.getElementById('connect-btn').click()` → `connectSerial('manual')` → Web Serial API
4. **dh-proto-apply 真正应用协议** (line 16027) — 写 `localStorage.serialcube.lastProtoId` + 调 `NS.renderKpiCards()` 重渲染 + toast + 关闭 modal
5. **NS._serialConnected 同步** (line 16983, 主应用 `updateSerialStatus` 末尾) — `dashNS._serialConnected = state.serial.connected;` 变化时调 `updateDashboardProtoBar()`
6. **updateDashboardProtoBar 改双条件** (line 12497-12510) — 占位区显隐看 `activeProtoId && proto && NS._serialConnected`, 串口未连时占位区也显示
