## 修复

### 1. dh-pair-trigger-modal HTML 结构错位（v1.2.1 遗留 bug）

**根因**: v1.2.1 删除 `openSelectProtocolModal()` 时重排 HTML，第 8369 行的 `</div>` 把 modal 提前关掉，导致 `<div class="modal-body">` 和 `<div class="modal-footer">` 漏在 modal 外部。modal `display: none` 时仍泄漏到主区底部显示。

**症状**: 仪表盘未连接状态下，主区底部一直显示"设置值 / 字节预览 (buildFrame) / —"空占位区（~250px 高度），v1.2.1 changelog 写"挪到 modal"但实际没执行干净。

**修法**: 把 modal-body / modal-footer 重新包回 modal 内，删多余 `</div>`。

**影响范围**: 整个 main 区域底部（不只是协议条），但因为 modal `display: none` 才显示不出来——结构修复后这块占位完全消失。

### 2. 协议条冗余元素清理

**根因**: 协议条 (line 7948) 5 个元素全冗余，参考用户反馈"红色框选区域没用，影响布局"。

| 元素 | 状态 | 处理 |
|---|---|---|
| `● 当前协议` / `○ 未激活` pill | 保留 | 文字改 "未选择协议" (更友好) |
| 协议名 `—` | 保留 | — |
| `未连接` (`#dh-dash-proto-port`) | **删除** | 跟左侧"连接设备 \| 当前未连接"重复 |
| `设置值` 按钮 (disabled 永远不可点) | 改 `display: none` 默认隐藏 | 已连接+已选协议时 `display: ''` 显示 |
| `切换/选择协议` 按钮 | 保留 | label 跟状态联动 |

**视觉效果**: 协议条从 5 元素 → 3-4 元素，节省 30-50px 高度 + 视觉清爽。
