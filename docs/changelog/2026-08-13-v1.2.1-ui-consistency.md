# v1.2.1 · 2026-08-13 · UI 一致性修复

## 主题

**4 modal header 统一 + 协议编辑 4 段重构 + 选协议 modal 合并**

一次性解决 v1.2.0 部署后用户实测反馈的 8 个 UI/UX 问题。

## User-facing 改动

### 1. 4 modal header 统一 (B2 决策)

新建 `.modal-header-standard` 共享组件，4 个 modal 一次对齐：

- **关闭 X 在右上** (`margin-left: auto`)，解决反人类位置
- **title 在左上**（font-weight 600 / 16px / var(--text)）
- **副标题在 title 下方**（var(--text-soft) / 12px）
- **面包屑在副标题下方**（11px / monospace / var(--text-soft)）

受益 modal：协议配置 / 协议编辑 / 命令编辑 / 告警编辑。

### 2. 协议编辑 modal 重构为 1 步长表单 4 段 (C3+ 决策)

v1.2.0 协议编辑 modal 渲染的是"单条命令配置"（重复了命令编辑 modal 职责），逻辑错位。v1.2.1 改为 schema 层管理：

| 段 | 内容 | 关键交互 |
|----|------|---------|
| **① 基础** | 显示名 / 内部 ID / 类型 / 标签（2×2 grid） | 字段失焦触发帧预览重算 |
| **② 帧预览** | 顶部 dropdown 选命令 + 实时 byte 序列 | 切换命令 debounce 150ms 重算 |
| **③ 帧字段** | 字段表 (name / type / len / endian / default) + "添加字段" | 字段编辑触发帧预览重算 |
| **④ 命令列表** | 命令表 (ID / name / dir / payload fields / 操作) + "新建命令" | 行内编辑跳到命令编辑 modal |

复用了：
- `NS.renderFramePreview(containerId, commandId)` 共享函数（从命令编辑 modal 抽出）
- 现有 `.frame-bytes .byte.{type}` 7 种类型色块（line 6707-6722）
- 现有 `.frame-preview` 样式（line 6701-6729）

### 3. "选择协议 modal" 合并到协议配置 modal (D1 决策)

独立"选择协议 modal"只做"3 选 1 + 记住选择"，认知负担高。v1.2.1 合并：

- **删除** `openSelectProtocolModal()` 函数（约 30 行）
- **删除** 独立"选择协议" modal 的 DOM / CSS
- **仪表盘"选择协议"按钮** 直接打开协议配置 modal（与系统菜单 → 配置中心 → 协议 tab 走同一 modal）
- **协议列表每行加"应用"列**（最左）：
  - ● 圆点（active = var(--accent) 蓝）
  - ○ 圆点（非 active = var(--text-soft) 灰）
  - 点 ○/● 即时切换 `NS.activeProtoId` + 仪表盘重渲染
- 新增 `NS.toggleActiveProtocol(id)` 函数

### 4. 仪表盘协议条改 (A1 + A2 决策)

- **删除"引导"按钮**（灯泡 icon，从未被使用）
- **加"⚙ 设置值"按钮**（"选择协议"按钮旁边）：
  - 打开条件：已连接串口 + 已选 activeProtoId
  - 否则 disabled（opacity 0.4 灰显）
  - 点击 → 打开 dashboard-settings-modal
- **删除仪表盘底部"设置值/字节预览"常驻区**（未连接时占 80% 调试初期，常驻只占空间）
- **新增 dashboard-settings-modal**：字段输入 + 复用 `NS.renderFramePreview()` 渲染 byte 序列

### 5. 协议配置 modal "新建协议"按钮去重 (D6 决策)

原来同一按钮 3 处入口（顶部 header 旁 / 内容区右上 / 底部 footer），用户分不清。

- **删除** 顶部 header 旁"新建协议"按钮
- **删除** 底部 footer"完成"旁的"新建协议"按钮（如存在）
- **只保留** 内容区右上"新建协议"按钮（离协议列表最近，最自然）

### 6. 抽 `renderFramePreview()` 共享函数

原本 v1.2 命令编辑 modal 内联帧预览渲染（line 7848-7856），抽出为共享函数：

```js
NS.renderFramePreview = function (containerId, commandId) {
  // ... 复用 buildFrame + .frame-bytes .byte.{type} 7 种色块
  // 失败 → 显示 "—" 占位
};
```

受益 modal：命令编辑（沿用 v1.2）/ 协议编辑 ② 帧预览段 / 仪表盘设置值。

### 7. 帧预览主题适配（v1.2.1 整体要求）

- 7 种 byte 色块全部用 `var(--*)` CSS 变量，禁止硬编码颜色
- 关键：`.byte.data { background: var(--bg) }` 而**不是** `var(--bg-terminal)` —— 故意让 data 段跟 frame 容器（`var(--bg-terminal)`）有**微差"切开"感**（SerialCube 原始设计意图 line 6720）
- 浅色模式：frame 浅灰 #f6f6f7，data 段 #ffffff 微差切开
- 深色模式：frame 深灰 #161618，data 段 #1b1b1f 微差切开
- `.modal-header-standard` 4 modal 在 2 个主题下都正确（title 文字 / X 按钮 / 副标题颜色都跟随 var 变量）

## 兼容性

- 导入 v1.2 配置 → `NS.activeProtoId` 默认 `null`，用户首次打开手动选（与 v1.2 行为一致）
- 旧仪表盘代码引用 `openSelectProtocolModal()` → 改用 `openConfigCenterModal('protocol')` + 行内"应用"列
- 命令编辑 modal 调用方不变（API 兼容），仅 DOM 改
