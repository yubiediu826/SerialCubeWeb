# v1.3.19 — 0x01 控制与常规数据 卡片补全 (BMS V1.13 §4 全部字段)

> **日期**: 2026-08-17 · **范围**: SerialCube.html 卡片生成层 + bms_v113.json schema · **改动量**: 4 个文件, 1 commit

## 背景

之前 v1.3.18 之前, 0x01 命令的卡片生成层 (`_generateSchemaCards`) 只用 12 个硬编码字段名生成 Device set 卡 + 4 个硬编码 bitset 字段, 协议里 0x01 完整字段 (BMS V1.13 §4.2 共 48 字段) 大量没生成卡片, 用户调试时缺关键遥测 (温度组、电流校准、容量统计、断开原因、剩余容量等)。

## 改动详情

### 1. Device set 卡 12 → 34 字段 (+ 22)

按协议表完整 0x01 字段清单补全, 跳过 RSVD 保留位 + 数组字段 (Cell_Temp[8]/Vcell[20] 暂不补, 等单独决策):

| 新增组 | 字段 | 数量 |
|--------|------|------|
| 温度组 | ChgMosTemp / DsgMosTemp / PreDsgMosTemp / AfeTemp / PcbTemp | 5 |
| 电流/校准 | AverageCurr / CurrGain / CurrOffset | 3 |
| SOC | ASOC | 1 |
| 容量统计 | AccumValue / TorageLossCap / TotalChargeCap / TotalDischargeCap | 4 |
| 电芯电压辅 | Vcell_dif / Vcell_max_num / Vcell_min_num | 3 |
| 总压/辅源 | AdapterVolt (旧名 BackupPowerVoltage) | 1 |
| 断开原因 | Chgdiscncause / Dsgdiscncause | 2 |
| 剩余/满电容量 | ARemainCap / RFCC / AFCC | 3 |
| **合计** | | **22** |

### 2. Device bitset 4 → 5 (+ SignalSource)

之前 SignalSource JSON 写的是 `type: u8`, 不被 `_generateSchemaCards` 当 bitset 处理 (条件 `f.type !== 'bitset'` 过滤掉)。
- JSON SignalSource: `type: u8` → `type: bitset` + 加 8 bit 占位定义 (位名 bit0-bit7, 详细位定义见协议附录 A16, 当前以占位填入, 待固件确认后细化位名)
- 白名单 `bsNames` 加 `SignalSource`

### 3. Host trend 6 → 12 字段 (+ 6)

按 Device 集扩的语义, Host 端 trend 也补 6 字段 (跟 Device set 子集重叠但用 trend 类型显示历史曲线):
ASOC / CellTempMin / Vcell_min / PackVolt / AverageCurr / AdapterVolt

### 4. JSON 字段命名修订

bms_v113.json `BackupPowerVoltage` → `AdapterVolt` (同位置 bit 1080, 协议修订对齐)。
RSVD0-4 命名差异 (协议表 RSVD1-5) 不改 — 保留位编号差异不影响功能。

### 5. `_fieldRange` map 扩展

加 22 字段合理量程:
- 温度: -20~120 ℃ (ChgMosTemp/DsgMosTemp/PreDsgMosTemp/AfeTemp), -20~100 ℃ (PcbTemp)
- 电流/校准: -50000~50000 mA (AverageCurr/CurrOffset), 0~200% (CurrGain)
- 容量: 0~200000 mAh (AccumValue/TorageLossCap/TotalChargeCap/TotalDischargeCap/ARemainCap/RFCC/AFCC)
- 电芯辅: 0~1000 mV (Vcell_dif), 1~20 (Vcell_max_num/min_num)
- 辅源: 0~300000 mV (AdapterVolt)
- 断开原因: 0~65535 (16b raw, Chgdiscncause/Dsgdiscncause)
