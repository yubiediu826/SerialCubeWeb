# v1.3.7 — 双页面主机/从机仿真 + 控制卡 + 卡片级数据源

**VERSION**: 1.3.6 → 1.3.7
**日期**: 2026-08-16
**类型**: feature + bug fix

## 背景

用户实测报 4 个问题：

1. 协议导入后缺失卡片（空白仪表盘）。
2. 打开两个页面（一主机一从机）时，`bms_v113_host` 和 `bms_v113_slave` 只能导入其中一个（旧逻辑把两者归一成同一个 `proto_bms_v113` 协议）。
3. 仿真模式背离初衷 — 应该支持主机/从机切换；主机模式要有"控制卡"下发控制命令（如 0x01 ctrl 位表），同时显示从机响应的遥测数据。旧卡片和协议编辑器都不支持。
4. 从机的随机/规律数据生成应该集成在卡片里，而不是单独的仿真 modal。

## 修复

### 1. 协议导入自动生成卡片

`importSchema` 现在对无卡片的 schema 协议自动生成默认卡片：
- 0x01 CB 关键遥测 trend 卡（RSOC / BatVolt / SysCurr / SOH / Vcell_max / CellTempMax）。
- 主机角色额外生成 0x01 控制卡（发送 ctrl + 显示 RSOC）。

### 2. host/slave 独立协议 + 角色

- `split-bms-schema.mjs` 重写：host/slave 文件改为**各含完整双向 schema**（frame + 全 19 命令 MB+CB），区别只在 `role` 标记 + 独立协议 id（`proto_bms_v113_host` / `proto_bms_v113_slave`）。双页面仿真中，主机页发 MB + 收 CB，从机页收 MB + 发 CB，两边都需要完整双向布局。
- `importSchema` 不再归一 id，保留独立协议；`role` 字段映射为仿真角色（host→host / slave→device）并自动切换。
- 导入前先合并 localStorage 里另一 tab 刚导入的最新协议（避免跨 tab 内存态覆盖）。
- 删除过时的 `merge-bms-schema.mjs`；`embed-schema.mjs` 直接嵌入 `bms_v113.json`，跳过 host/slave 视角副本。

### 3. 控制卡（主机模式核心）

- 新卡片类型 `control`：`cmd` + `schemaDir:'MB'` + `field`(ctrl 位表) + `respField`(遥测响应)。
- 渲染：ctrl 位表按位切换按钮（Load / AC_Adapter / DC_Adapter / ShutDown / Adapter_Enable / normal_power / Sleep / Test_mode / calibrate_mode / fan_enable）+ "发送"按钮 + 响应遥测值（如 RSOC）。
- 发送：`_buildFrameSchema` 组 MB 帧 → `_writeSerial` 写串口；解析回帧后 `currentVals` 更新响应字段。
- 卡片编辑 modal 新增类型选项 + 响应字段下拉（只列 CB 方向字段）+ 保存时回填 schemaDir/respField/respUnit。
- 趋势布局 + 列表布局都支持控制卡（列表卡带发送按钮 + tx 状态环）。

### 4. 卡片级从机数据源

- 卡片编辑 modal 新增"从机数据源"段（固定/随机/正弦/斜坡 + 参数）。
- 卡片存 `sim` 对象；`_deviceRespond` 生成 CB 响应字段值时，**卡片数据源（card.field → card.sim）优先于全局 `_simSources`**。
- 仿真角色 `_simRole` 持久化到 localStorage，双页面各记各的角色。
