# v1.3.16 — 新建/编辑命令 modal 数据字段优化 (2026-08-17)

## 概述

新建/编辑命令 modal 数据字段 49 行无折叠分组、位定义列对非 bitset 字段无意义、df-dir.tx 用警告色错配、行高 24px 偏小、添加字段模板化缺失、字段方向默认"— 无"应跟 cmd 方向、批量默认值按钮无 handler。8 项 P0/P1 一波优化, modal 完整体验大改。

## 改动

### P0-1 数据字段按方向分组 (RX 折叠 / TX 展开)

v1.3.15: 49 行全展开, 需 modal-body 内部 scroll 5-6 次才能看完, UX 差

v1.3.16: 3 个 df-group (TX / RX / BOTH), 各自 sticky thead
- TX 发送 默认**展开** — 调试命令时关注 "我发什么"
- RX 接收 默认**折叠** — 32 字段响应可折叠
- TX+RX 双向 / 未设 展开

分组 header 显示 "· N 字段 · M 字节" 计数, 折叠时显示箭头旋转

### P0-2 仅 bitset 字段显示位定义

v1.3.15: bitsEditorHtml 无条件渲染, u8/u16/f32 字段也显示 "暂无位定义" + "+ 添加位" 误导

v1.3.16: `if (df.type !== 'bitset') return '<span class="bit-na">' + df.type + ' 无位定义</span>'`
- u8 / i8 / u16 / i16 / u32 / i32 / f32 / f64 / bytes 显示 "u8 无位定义" 灰字
- 仅 bitset 字段显示位编辑器 (8/16 位) + 添加位按钮

### P0-3 df-dir 颜色 token 化 (复用 v1.3.12 footer-direction)

v1.3.15: `.df-dir.tx` = `#d97706` (hardcoded 警告色) — TX 发送 ≠ 警告, 误导

v1.3.16: 4 个 token 加 :root + 暗色/浅色主题适配
- `--dir-tx-fg: var(--signal)` (蓝 发送)
- `--dir-rx-fg: var(--success)` (绿 接收)
- `--dir-both-fg: #6b21a8` (紫 双向, 浅色 `#6d28d9`)
- `--dir-none-fg: var(--text-soft)` (灰 无)

方向列从 `<select>` 改为 4 button 按钮组 (TX/RX/TX+RX/—), 颜色按 current dir 应用, 视觉对比清晰

### P1-1 行高 30→36px, input/select 宽 80→120/140/110

v1.3.15: `.wiz-field-table input/select { padding: 3px 6px; ... font-size: 12px; width: 80px; height: 24px }` — 24px 输入框偏小, 80px 名字看不全

v1.3.16: padding 5/8, font-size 13px, height 30px, 名字 140px / 默认值 100px / 类型 110px
- 行高 36px, 信息密度 OK + 触达 WCAG 大字 12px+

### P1-2 添加字段按钮拆 3 模板 (+ u8 / + u16 / + bitset)

v1.3.15: 单一 "+ 添加字段" 添加空字段, 用户得手动改 5 项 (类型/方向/默认值/名字)

v1.3.16: 3 个模板按钮, 覆盖 80% 场景
- + u8 字段 (1 字节无符号)
- + u16 字段 (2 字节无符号)
- + bitset 字段 (1 字节位段, 自动 8 位)
- 添加即用 (类型已选), 方向自动 follow cmd.direction

### P1-3 字段方向默认 follow cmd.direction, override 保留

v1.3.15: 字段添加时 `df.dir = undefined` → 渲染 "— 无", 用户得手动改

v1.3.16:
1. 添加字段时 `df.dir = s.direction` (cmd.direction)
2. 用户改 df-dir-btn 时设 `df._userDirSet = true` (per-field override 标记)
3. 改 cmd.direction 时, 遍历 dataFields, 只 sync 未 _userDirSet 的字段
4. 已 override 的字段保持原方向

### P1-4 "批量默认值" → "重置默认值为 0" 真实实现

v1.3.15: "批量默认值" 按钮 onclick 用 prompt 让用户输入 hex 值, 但跟按钮名 "批量" 矛盾, 用户期望一键重置

v1.3.16: 改名 "重置默认值为 0", onclick 直接 `df.default = '0'`, toast 提示

### P2-1 删除按钮 24×24 → 32×32 click target

v1.3.15: `.wiz-field-del { padding: 4px; ... }` — 24×24 偏小, 不达 WCAG click target 32×32

v1.3.16: `width: 32px; height: 32px; display: inline-flex; align-items: center; justify-content: center` + 32×32 lucide trash 图标, 4px 圆角
