# v1.3.18 — 设备连接管理 3 项改进 (2026-08-17)

## 概述

3 项设备连接管理面板改进一波落地:
1. **组帧超时新功能** — 解决从机连续发无换行帧 (如 `5A 01 01 02 00 00 91 1D`) 时 log 挤在一块的问题。`queueRxBytes` 加 idle 计时器, 无新字节超过阈值自动 finalize 当前累积 event
2. **默认 16 进制 RX/TX** — 复用现有 十六进制接收/发送 checkbox, 改 `state.settings.rxDisplayMode` + `sendMode` 默认值, init 函数自动设 checked
3. **下拉框高度统一** — `.config-panel .field input/select` padding 从 7px 升到 9px, 跟 `.baud-rate-combo` 同高

## 改动

### A. 组帧超时 (主功能)

#### A.1 HTML 新字段

`SerialCube.html:7884-7887` 在 `校验位` 之后加:

```html
<div class="field">
  <label for="frame-timeout">组帧超时</label>
  <input id="frame-timeout" type="number" min="0" max="2000" step="10" value="50">
</div>
```

注意: `.config-grid` 实际是 2 col (不是 4 col), 5 字段在 2 col 中变 3 行 (跟用户 Q2 假设 "5 col" 不同, 但视觉上接受)。

#### A.2 State + 持久化

- `state.settings.frameTimeout = 50` 默认 (line 9321)
- `state.serial._frameTimeoutId = null` (line 9287)
- 持久化走现有 `applyLocalPrefsSnapshot` 路径, 跟 `pairTriggerTimeout` 同模式 (line 30124-30127 normalize 加 0-2000 验证)
- 不新增 localStorage key

#### A.3 JS timer 逻辑

**`queueRxBytes` 末尾 (line 24257) 调 `scheduleFrameTimeout()`** — 每次新字节来 reset timer。

**helper 函数 (line 24261-24271)**:

```javascript
function scheduleFrameTimeout() {
  if (state.settings.frameTimeout > 0 && state.serial.rxActiveEvent) {
    clearTimeout(state.serial._frameTimeoutId);
    state.serial._frameTimeoutId = setTimeout(flushFrameByTimeout, state.settings.frameTimeout);
  }
}
function flushFrameByTimeout() {
  state.serial._frameTimeoutId = null;
  if (state.serial.rxActiveEvent) {
    finalizeRxActiveEvent(nowPreciseMs(), { processRules: true, syntheticSplit: true });
  }
}
```

#### A.4 disconnect 集成

`disconnectSerial` 入口 (line 25321-25326) 加 clearTimeout + finalize 当前累积 event, 避免尾巴字节丢失。

#### A.5 input change 事件

`refs.frameTimeout` 加 `change` 监听 (line 31439-31453):
- 失焦/回车才生效 (避免每键入重置 timer)
- 验证 0-2000 整数, 错误还原 + toast 警告
- 写 state + clearTimeout + 重 schedule + 持久化 (`scheduleLocalPrefsSave`) + toast 成功

- 持久化走现有路径 (跟 v1.3.18 frameTimeout 共享)
