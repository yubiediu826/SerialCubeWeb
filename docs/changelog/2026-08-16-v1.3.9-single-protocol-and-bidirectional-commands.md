# v1.3.9 — 单一协议 + 双向命令 + 协议编辑器修复 + 位编辑器 + 单弹窗建卡 + 控制位拆卡

**VERSION**: 1.3.8 → 1.3.9
**日期**: 2026-08-16
**类型**: 架构重构 + bug fix + UX 优化

## 背景

用户反馈 5 个问题：

1. 协议编辑器编辑命令字段为空、大小为 0，但命令列表又显示 122 字段。
2. 新建命令时位定义编辑困难（逗号分隔文本）。
3. 新建卡片分步应合并为单弹窗；主机模式卡片应支持字段中的单个位（保护标志等按位数据）。
4. 主机模式控制字段位定义缩在一张卡不方便。
5. 协议配置问题：一个 json 就够了，仪表盘通过主机/从机模式区分；0x01 主机只发 2 字节控制字段、从机回多字节，当前协议只有 tx 没有 rx。

## 修复

### P1 — 单一协议 + 双向命令模型

- 删除 `bms_v113_host.json` / `bms_v113_slave.json` / `split-bms-schema.mjs`，回到唯一 `bms_v113.json`。
- `_registerSchemaProtocols` 只注册单一 `proto_bms_v113`（完整双向 schema）。
- `_schemaCommandList` 给命令同时承载 `txFields`/`txLen`(MB) + `rxFields`/`rxLen`(CB)：
  - 0x01：tx = ctrl bitset（2B），rx = 48 字段遥测（159B），direction=`both`。
  - 0x02：tx = 保护参数（95B），rx = ack（1B），direction=`both`。
- `setSimMode` 只切 `_simRole`，不再切 activeProtoId（模式=角色，不是协议）。
- 命令 tab 方向列显示「TX+RX 双向」pill。

### P2 — 协议编辑器字段/大小修复

- `openNewCommandModal` 编辑 schema 命令时从 `txFields`/`rxFields` 派生 `dataFields`（含方向 TX/RX 标注、bitset 位定义、bitLen/startBit），修复「字段为空」。
- `computeDataSize` 对 schema 命令按 `txLen + rxLen` 算，修复「大小为 0」。
- `_saveNewCommand` 保留 `txFields`/`rxFields`/`txLen`/`rxLen`/`schemaDir`，编辑不丢失双向布局。

### P3 — 位定义编辑器

- `_renderNewCmdDataFields` 位定义从「逗号分隔文本」改为**逐位表格**：每行位号 + 位名 + 删除按钮，「+ 添加位」逐位增删，保存映射回 `bits[]`。

### P4 — 单弹窗新建卡片 + 主机单bit

- `_openNewCardWizard` 合并为单弹窗：协议 + 命令 + 类型（trend/control/set）+ 字段 + 标题，一次保存即建卡。
- 字段下拉用 `_cardFieldOptions`（含 bitset 位展开如 `ProtectCode.软件层放电过温保护`）；选「control」类型 + `字段.位名` 形式自动生成单bit 控制卡。

### P5 — 0x01 控制位拆卡

- `_generateSchemaCards('host')` 把 0x01 ctrl 位表拆成**每位一张单bit 控制卡**（Load / AC_Adapter / DC_Adapter / ShutDown / Adapter_Enable / normal_power / Sleep / Test_mode / calibrate_mode / fan_enable，共 10 张），Reserved 位不生成。
- 单bit 卡渲染：位名 + ON/OFF 状态 + 开启/关闭切换 + 发送 + RSOC 响应显示。
