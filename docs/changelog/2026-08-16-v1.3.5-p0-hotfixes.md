**背景**: 全面评审（[docs/review/2026-08-16-code-quality-and-workflow-review.md](../review/2026-08-16-code-quality-and-workflow-review.md)）后的首个止血版本。

## 修复清单

### 1. mock tick 连接守卫（仪表盘从"动画"变回"测量"）
- `NS.tickData` 开头加 `if (NS._serialConnected) return;` — 真实串口已连接时禁止每 800ms 的随机抖动覆盖 `currentVals`（旧行为会把真设备解析值冲掉）。
- mock/未连接模式行为不变（演示动画保留）。

### 2. 告警对象比较 bug（告警变色/文案恢复生效）
- `renderCard` trend 卡分支：`checkAlert` 返回 `{ severity }` 对象，旧代码 `alert === 'danger'` 字符串比较恒 false，导致 ALARM/WARN 状态与变色从未出现。统一改为取 `sev = alert ? alert.severity : null` 后比较。

### 3. checkAlert 无参调用修复
- `NS._injectMutation` 客户端路径 `NS.checkAlert()` → `NS.checkAlert(v, fieldName)`（旧无参调用直接返回 null，Mutator 注入后告警永不触发）。

### 4. float / double 编码对称（IEEE754）
- `NS.encodeDataFields` 的 float 分支旧实现 `Math.round(v)` 按整数写 4 字节，与解码 `_bytesToNumber` 的 `getFloat32` 不对称，往返必错；double 声明但无编码分支（静默丢字节）。
- 改为 DataView `setFloat32/setFloat64` 按字节序编码，补 double 分支。

### 5. 类型表单一数据源
- `NS.DATA_TYPES` 补 `i8` / `double`（旧表缺这两项，与 `_FIELD_BYTE_SIZE` 不一致）；`_FIELD_BYTE_SIZE` 改为由 `DATA_TYPES` 派生，消除双表漂移。

### 6. ⚠️ CRC16-Modbus 修正为标准算法（真机互操作，评审 + jsdom 冒烟发现）
- 旧实现是 MSB-first 变体，**不等同标准 CRC-16/MODBUS**。与 BMS 协议文档实算帧对比：`5A 01 03 01 00` → 标准 0x618C / 旧实现 0xE580。
- 后果：应用构造的帧会被真 BMS 设备拒绝，真设备帧校验必失败（接真设备"没反应"的根因之一）。
- 已改为标准 LSB-first（poly 0xA001, init 0xFFFF），与 BMS 协议文档 Python 实现一致；冒烟测试以 5 组文档黄金向量回归（见 `.tmp/smoke.mjs`）。
- 同步修正 `docs/reference/CRC-REFERENCE.md` §2.1（旧"经典测试向量 0xC5CD"是旧实现的伪向量，已废弃并给出正确向量表）。

### 7. XSS 转义（调试面板）
- `_populateDebugMutatorFields` 的 `<option>` 与 `_renderDebugPresets` 的 chip（label/tip）拼接 innerHTML 前补 `NS.escapeHtml`（字段名/范围/单位来自用户可编辑卡片并持久化，可注入）。

### 8. link-check 脚本 2 处 bug（docs/guides/DEVELOPER-GUIDE.md §13.1）
- 跳过正则 `'^(https?:|mailto:|#|\.)'` 里的 `\.` 会误吞所有 `../`、`./` 相对链接 → 去掉 `\.`。
- `$_.Matches[0]` 每行只查第一个链接 → 改为遍历 `$_.Matches` 全部匹配。
