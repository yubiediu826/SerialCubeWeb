# v1.3.10 — 串口日志换行 + 卡片分组与角色区分 + 编辑器 UX 修正

**VERSION**: 1.3.9 → 1.3.10
**日期**: 2026-08-16
**类型**: bug fix + UX 优化

## 背景

用户反馈 7 个问题：

1. 串口监视器日志不会自动换行，挤成一块。
2. 主机模式下 0x01 控制卡与从机响应卡挤在一起，响应卡显示不全。
3. 从机模式下同字段仍显示 trend 显示卡而非 set 可配置卡，未区分角色。
4. 控制卡显示 RSOC 字段数值（无意义）。
5. 协议编辑器显示 TX+RX 双向，但新建命令方向下拉没有双向选项。
6. 编辑命令帧预览单行不换行，默认值全 0 应有实际预览值。
7. 新建卡片字段下拉中「位」与「字段」混在一起不好配置。

## 修复

### P1 — 串口日志自动换行

- `.log-line` 与 `.log-line .payload` 从 `word-break: break-word`（无效值）改为 `word-break: break-all; overflow-wrap: anywhere`，长 hex/无空格文本自动折行。

### P2 — 卡片分组与角色区分

- `renderCardGrid` 分组 key 从 `c.cmd` 改为 `cmd + 类型段`：control 与 trend/set 分开成组，组头分别标注「0x01 控制 (TX)」「0x01 响应 (RX)」「0x01 参数 (RX 配置)」，不再挤在一起。
- `renderGroupHeader` 支持 `both` 方向 badge 样式。
- `_cardVisibleInRole` 角色区分：host → control + trend；device → set（trend 不再两角色混显）。同字段（如 RSOC）主机显示 trend 显示卡、从机显示 set 可配置卡。

### P3 — 控制卡去响应值

- 单bit 与多位控制卡渲染移除 `ctrl-resp` 行；`_generateSchemaCards` 与新建卡片向导不再给控制卡带 `respField/respUnit`。响应观察由独立 trend 卡承担。

### P4 — 方向 both + 帧预览

- `dh-new-cmd-direction` 增加 `<option value="both">TX+RX (双向)</option>`。
- `.frame-bytes` 从 `white-space: nowrap` 改为 `normal + word-break: break-all`，长帧自动换行。
- 帧预览使用非零预览值：schema 字段自带 `default` 优先（0x02 有真实默认值），无 default 用 `0x01` 占位（不再全 0）；`openNewCommandModal` 派生字段携带 schema `default`。

### P5 — 字段下拉分组

- `_cardFieldOptions` 选项带 `isBit` 标记；新增 `_fieldOptionGroupsHtml` 用 `<optgroup>` 分「字段」/「位 (bitset 展开)」两组。
- custom-select 浮动菜单支持 optgroup：分组标题渲染为不可点击 label，组内选项缩进。
- `openCardEdit` 与新建卡片单弹窗字段下拉都使用分组渲染。
