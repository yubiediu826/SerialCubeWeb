# v1.3.3 — 协议配置中心 3 tab 按 activeProtoId 过滤

> **发布日期**: 2026-08-14
> **触发原因**: 用户实测 v1.3.2 协议配置中心 — 选 modbus 协议后,顶部 tab 计数 + 卡片/告警内容仍显示 bms 协议的数据
> **影响范围**: 协议配置中心 modal 的 4 个 tab (protocols / commands / cards / alerts) 全部受影响

---

## 1. 根因分析

v1.3.2 修复了仪表盘的 activeProtoId 过滤(命令 panel / 卡片区 / 告警列表),但**没改协议配置中心**。具体 3 处:

| 位置 | 旧实现 | 问题 |
|------|--------|------|
| 顶部 badge `命令/卡片/告警` 计数 | `NS.allCommands().length` / `NS.CARDS.length` / `NS.ALERTS.length` | 跨协议总数,选 modbus 还显示 8/12/0 (bms 的) |
| `commands` tab 协议下拉 | `NS._ccSelectedProtoId \|\| PROTOCOLS[0].id` | 独立状态,不跟 activeProtoId 联动,默认显示 bms 8 条命令 |
| `cards` / `alerts` tab 表格内容 | `NS.CARDS.map` / `NS.ALERTS.map` 不过滤 | 选 modbus 还显示 bms 12 张卡片 |

8 处直接操作 badge 的代码 + 1 处 `_renderConfigCenter` 内部 = 9 处都得改。

---

## 2. 修复方案

### 2.1 抽公共函数 `_refreshConfigCenterBadges()`

替换 9 处分散的 badge 更新代码为统一函数,内部按 `activeProtoId` 过滤:

```js
NS._refreshConfigCenterBadges = function () {
  const protoId = NS.activeProtoId;
  // 命令数: 跨协议 flatMap 后按 activeProtoId 过滤
  let cmdsForActive;
  if (protoId) {
    const p = NS.PROTOCOLS.find((pp) => pp.id === protoId);
    cmdsForActive = (p && p.commands) || [];
  } else {
    cmdsForActive = typeof NS.allCommands === 'function' ? NS.allCommands() : [];
  }
  // 卡片数 / 告警数: 按 c.protocol / a.protocol === activeProtoId
  const filterByActive = (arr, key) => (arr || []).filter((x) => !protoId || x[key] === protoId);
  const cardsForActive = protoId ? filterByActive(NS.CARDS, 'protocol') : (NS.CARDS || []);
  const alertsForActive = protoId ? filterByActive(NS.ALERTS, 'protocol') : (NS.ALERTS || []);
  // 写 badge
  const cmdBadge = document.getElementById('dh-cc-commands-badge');
  if (cmdBadge) cmdBadge.textContent = cmdsForActive.length;
  // ...card + alert 同理
};
```

**关键设计**:
- `activeProtoId` 为 null 时回退到跨协议总数 (向后兼容 — 没选协议时仍能看到全部)
- 旧函数 `_refreshAlertsBadge` delegate 到新函数 (5 处现有调用点零改动)

### 2.2 `commands` tab 协议下拉默认值

```js
// 旧:
const selProtoId = NS._ccSelectedProtoId || (NS.PROTOCOLS[0] && PROTOCOLS[0].id);

// 新 (activeProtoId 优先):
const selProtoId = NS.activeProtoId || NS._ccSelectedProtoId || (NS.PROTOCOLS[0] && PROTOCOLS[0].id);
```

### 2.3 `cards` / `alerts` tab 表格内容

```js
// cards
const cardsScoped = NS.activeProtoId
  ? (NS.CARDS || []).filter((c) => c.protocol === NS.activeProtoId)
  : (NS.CARDS || []);
// alerts
const alerts = NS.activeProtoId
  ? (NS.ALERTS || []).filter((a) => a.protocol === NS.activeProtoId)
  : (NS.ALERTS || []);
```

toolbar 文字加 "已按当前激活协议 X 过滤 / 全部协议" 提示,避免用户以为数据丢了。

### 2.4 修复行 idx 错位 (副作用 bug)

过滤后 `cardsScoped.map((c, i) => ...)` 里的 `i` 是 **filtered 局部下标**,但编辑/删除按钮 handler 用 `NS.CARDS[idx]` 拿 **全局下标** — 选了 modbus 之后,点 modbus 卡片编辑会打开 bms 卡片。

```js
// 旧: data-card-index="i"  (filtered 局部下标)
//     handler: NS.CARDS[idx]  (全局下标, 错位!)

// 新: 用全局下标
const globalIdx = (NS.CARDS || []).indexOf(c);
return '<tr data-card-index="' + globalIdx + '">' + ...;
```

`alerts` tab 同根因,同步修复 (line 14975-14995)。

## 5. 关键决策

- **用 1.3.3 不用 1.3.2.1.1**: bump-version.ps1 只支持 3 段版本号,4 段会报错。1.3.3 是干净命名,涵盖 1.3.2.1 之外的所有未发版修复。
- **activeProtoId=null 回退到全部**: 而不是"全 0"或"隐藏" — 保留向后兼容(没选协议的用户仍能看到所有内容)
- **toolbar 文字加"已按 X 过滤"提示**: 避免用户误以为"卡片丢了"或"告警删了",明确告诉用户当前看的是哪个协议
- **行 idx 改全局下标 (indexOf)**: 而不是保留 idx + 在 handler 里做 idx 映射 — 全局下标更直观,过滤逻辑只影响显示不影响操作

## 9. v1.3.3 追加 (用户连续反馈 3 个新问题)

> 用户反馈 3 个新问题:
> 1. 协议未激活为什么 tab 显示命令 8, 卡片 6?
> 2. 默认删除协议就是全部删除包含相关的卡片, 命令, 告警, 同时修改 UI 样式
> 3. 为什么我删除协议重新刷新浏览器又显示之前删除的协议?

### 9.1 badge 严格按 activeProtoId 过滤 (问题 1)

**问题**: `_refreshConfigCenterBadges` 没选时回退到 `NS.allCommands().length` / `NS.CARDS.length` / `NS.ALERTS.length` 跨协议总数, 用户问"为什么未激活 tab 还显示 8/12"

**修复**: 改成"没选 = 0/0/0",跟 tab 内容"未选占位"一致,跟仪表盘"未连接串口"逻辑对齐:
```js
// 改前: 没选回退到全部
cmdsForActive = protoId ? (...) : (typeof NS.allCommands === 'function' ? NS.allCommands() : []);
// 改后: 严格 0
cmdsForActive = protoId ? (p && p.commands) || [] : [];
```

### 9.2 协议删除改简单 confirm (问题 2)

**问题**: 之前用三选项级联 modal (`_openCascadeModal`) 让用户选"仅删自己" / "级联删除 (21)" / "取消",用户觉得"复杂/不安全"。

**修复**: 协议删除改为简单 `window.confirm`:
- 无引用: `"确认删除协议 proto_modbus?\n\n该协议无引用对象"`
- 有引用: `"确认删除协议 proto_bms?\n\n引用对象会一起删除: 8 条命令 + 12 张卡片 + 0 条告警"`
- 用户确认 → 直接级联删 (协议 + 所有引用对象)
- 命令/卡片删除仍保留三选项 modal (用户可二选一, 仅协议默认级联)

### 9.3 协议/命令/卡片/告警自动持久化 (问题 3)

**问题**: 之前只 `NS.exportConfig` 手动导出, 没有自动保存。`NS.PROTOCOLS = NS._defaultProtocols()` 在每次页面加载时重新生成默认 2 个协议 (bms + modbus), 删了协议刷新就回默认。

**修复**: 加 `NS._loadUserConfig` / `NS._saveUserConfig` / `NS._clearUserConfig`:
- 启动时 `_loadUserConfig` 从 localStorage 读 `serialcube.userConfig.v1` 覆盖 `_defaultProtocols()` / NS.CARDS / NS.ALERTS / activeProtoId
- modify 路径 (切协议 / 删除协议 / 复制 / 导入 / 新建/删除/编辑 命令/卡片/告警 / 重置) 显式调 `_saveUserConfig` 写 localStorage
- `NS.reset` 调 `_clearUserConfig` 清 localStorage + 用 `_defaultProtocols()` / `_defaultCards` 副本恢复默认
- `_defaultCards` 副本在 `NS.CARDS = [...]` 默认值后立即 `JSON.parse(JSON.stringify(NS.CARDS))` 保存, 确保 _loadUserConfig 覆盖前的"纯默认"快照

**实测**:
- 删 bms 协议 → 刷新 → 仍是 1 个协议 (modbus) ✓
- 切到 modbus 协议 → 刷新 → 仍是 modbus 激活 ✓
- 改 / 删 / 增 卡片/告警 → 刷新 → 保持 ✓
- "重置为默认配置" → 清 localStorage + 恢复 _defaultProtocols + _defaultCards ✓

**关键代码**:
```js
NS._USER_CONFIG_KEY = 'serialcube.userConfig.v1';
NS._loadUserConfig = function () { /* 从 localStorage 读 + 覆盖 PROTOCOLS/CARDS/ALERTS/activeProtoId */ };
NS._saveUserConfig = function () { /* 写 localStorage JSON.stringify */ };
NS._clearUserConfig = function () { /* removeItem */ };
// 启动时调用 (在 NS.CARDS 默认值定义之后, 避免被覆盖)
NS._loadUserConfig();
```
