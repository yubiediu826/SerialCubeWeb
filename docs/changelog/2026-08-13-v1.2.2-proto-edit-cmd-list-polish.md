# v1.2.2 — 协议编辑器命令列表打磨 + 帧预览 bug 修复 (2026-08-13)

本轮针对用户反馈的 4 项 UI 问题做集中修复, 同时定位并修了一个潜在已久的 inline handler bug.

## 🐛 重大 Bug 修复

### BUG: 帧预览 dropdown 切换后 bytes 不更新

**根因**: `const NS = ...` 不会挂到 `window`, 但协议编辑器的 frame preview dropdown 用的是
inline attribute 形式 `onchange="NS._protoEditFrameCmdChange()"`. 当浏览器解析 inline
`onchange` attribute 时, 会在 element scope → window 链上找 `NS` 这个标识符 —
而 `const` 变量不会自动成为 window 属性, 所以 `NS` 是 `undefined`, handler 静默报
`ReferenceError` 后中断. 表现为: 用户切 dropdown, 视觉上选项变了, 但 frame bytes
和命令列表都不刷新.

**影响范围**: 4 处 inline handler 全部受影响 (之前都是 disabled 或被 fast path 绕过所以没人发现):
- `dh-proto-frame-cmd-select` (帧预览 dropdown) — 严重
- `dh-dash-settings-btn` (仪表盘⚙按钮) — disabled 状态, 用户没碰到
- `dash-settings-modal` close X — 用户没点过

**修法**: 在 SerialCube.html line 10245 `const NS = ...` 后面加一行 `window.NS = NS;`,
让所有 inline `on*="NS.xxx()"` 都能正常找到 NS. 改动 1 行, 修复 4 处.

```js
const NS = window.__serialWebDashboard = window.__serialWebDashboard || {};
window.NS = NS;  // v1.2.2: 挂 NS 到 window, 让 inline on* handler 也能找到
```

**验证**:
- 切到 `0x03 Read Temp` → bytes 实时更新为 `AA 01 03 02 00 00 BE FF 55` (9 字节)
- 切到 `0x10 Control Charge` → bytes 实时更新为 `AA 01 10 04 00 00 00 00 6B 59 55` (11 字节)
- 命令列表对应行同步高亮 (`cmd-row-active` class + 浅绿底 + "— 当前帧预览" 标签)

## 🎨 UI 打磨 (基于用户截图反馈)

### 1. 帧预览段 — 横向单行 (不再 wrap)

**问题**: `.frame-bytes` 用了 `word-break: break-all`, 在窄容器里 9 字节就被 wrap 成 2 行.
用户问"是不是宽度太窄了" — 实际上是 word-break 强制 break 造成的.

**修法**:
```css
.frame-preview { overflow-x: auto; overflow-y: hidden; }
.frame-bytes  { white-space: nowrap; }
```

内容超长时容器出现横向 scroll, 不再断行.

### 2. 命令列表 — 表格列对齐 + 间距

**问题 1**: DIR / FRAMETYPE / CADENCE 三个 th 贴紧, 视觉上像黏在一起.
**问题 2**: 标题/字段未统一对齐 (cadence 是 right, 其它是 left, 操作 right).

**修法**:
```css
.cmd-list-table thead th { padding: 10px 14px; white-space: nowrap; }
.cmd-list-table thead th.col-dir     { width: 70px; }
.cmd-list-table thead th.col-frame   { width: 120px; }
.cmd-list-table thead th.col-cadence { width: 110px; }   /* 全部 left-align */
.cmd-list-table thead th.col-actions { width: 76px; text-align: right; }
.cmd-list-table td                    { padding: 9px 14px; }
.cmd-list-table td.col-cadence        { color: var(--text); }  /* 去掉 right-align */
```

**效果**: 全部 6 列 left-align, 列与列之间最小 14px 间距, 操作列固定 76px 靠右.

### 3. 命令列表 — 操作按钮间距 + hover 反馈

**修法**:
```css
.cmd-actions { display: inline-flex; gap: 6px; opacity: 0.55; }
.cmd-list-table tbody tr:hover .cmd-actions,
.cmd-list-table tr.cmd-row-active .cmd-actions { opacity: 1; }
.cmd-list-table tbody tr:hover { background: rgba(47, 111, 94, 0.05); }
.cmd-list-table tr.cmd-row-active { background: rgba(47, 111, 94, 0.08); }
```

每个 icon button 28×28, 之间 6px gap, 默认半透明 0.55, hover 行时 1.0, 当前帧预览行常驻 1.0.

### 4. 命令列表 — 去掉灰色背景

**问题**: 命令列表段之前套在 `.frame-preview` 里, 用了 `var(--bg-terminal)` 灰底,
跟命令列表本身的语义不符 (frame-preview 是给帧预览用的).

**修法**: 新增 `.cmd-list-wrap` 容器, 透明背景 + 边框, 只用 row divider 分割行.

```css
.cmd-list-wrap { border: 1px solid var(--border); border-radius: 6px; overflow: hidden; }
.cmd-list-table { background: var(--bg); }  /* 跟 modal body 背景一致, 无突兀 */
```

### 5. 命令列表 — 当前帧预览行同步高亮

**修法**:
- `_renderProtoEditCommandsSection(proto, currentFrameCmdId)` 接收当前 cmdId
- 切换 dropdown 时 `_protoEditFrameCmdChange` 末尾调 `_renderProtoEditCommandsSection(proto, cmd.id)`
- 旧段用 `.dh-cmd-list-section` class 标记, 新段先 remove 旧段再 append
- 表格行根据 `c.id === currentFrameCmdId` 加 `cmd-row-active` class + "— 当前帧预览" 标签
