## 经验

- **回滚前必看 GitHub 真实状态** — 本机 git log 跟远程分歧时, 优先用 `git ls-remote` 或 `web_fetch` API 看远程, 不要凭本机状态决策
- **force-push 之前先 backup 当前工作区** — `git checkout -b backup-<date> && git add -A && git commit` 把未提交内容存到独立分支, 防止 reset --hard 丢工作
- **git proxy 故障时用 inline config** — `git -c http.proxy= -c https.proxy= <cmd>` 绕开全局代理配置, 适合本机代理挂掉但 HTTPS 直连通的场景
- **force-with-lease 在 reset 后会拒绝 push** (stale info) — reset 后 lease 失效, 此时要么 fetch 更新 ref (代理挂时不通), 要么用 `--force` (私有仓库 OK)
- **回滚事件按 CHANGELOG.md 工作流要写子文件** — 跟普通 commit 一样, force-push 改 main 状态也要留 changelog 记录
