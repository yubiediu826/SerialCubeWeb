✗ v1 旧模型 (你提的问题)

NS.DATA_FIELDS = [
  { name: 'cell_1_v', type: 'u16', default: '0x0000' },
  { name: 'charge_v_set', type: 'u16', default: '0x0000' },
  // ... 11 个全局字段

    // ⚠ 字段名引用, 含义散在全局
  }

NS.PROTOCOLS = [{

  // ⚠ 命令不在协议里, 字符串引用松散

✓ v2 新模型 (推荐)

// 类型库: 小的, 全局, 8 种类型
NS.DATA_TYPES = [
  { name: 'u8',  size: 1 },
  { name: 'u16', size: 2, byteOrder: 'BE' },
  { name: 'u32', size: 4, byteOrder: 'BE' },
  { name: 'i16', size: 2, byteOrder: 'BE' },
  { name: 'float', size: 4, byteOrder: 'BE' },
  // ...
];

// 协议自包含: 帧模板 + 命令列表
NS.PROTOCOLS = [{
  id: 'proto_bms', name: 'BMS TLV v1', kind: 'fixed-header',
  fields: [/* 帧模板: header/addr/length/data/crc/tail */],
  crcType, crcInit, ...,
  commands: [
    {
      id: 0x01, name: 'Read Voltage', direction: 'rx',
      frameType: 'query', cadence: 200,
      dataFields: [                       // ← 命令自带
        { name: 'cell_1_v', type: 'u16', default: '0x0000' },
        { name: 'cell_2_v', type: 'u16', default: '0x0000' },
        // ...
      ]
    }
  ]
}];

// helper 垫片, 给 cards 用
NS.allCommands = () =>
  NS.PROTOCOLS.flatMap(p => p.commands || []);

6改造范围 — 还是 ~250 行, 但分得更细

  • 数据模型 ~50 行: PROTOCOLS[i].commands[].dataFields[] 嵌套结构, NS.allCommands() 垫片
  • 新建协议向导 ~120 行: 3 步状态机 + kind 预填逻辑 + 表单验证
  • 新建命令 modal ~80 行: 表单 + 字段 chips 增删 + 字节数自动算
  • 协议编辑器主 modal ~80 行: tab 切换 + 命令表格 + 详情面板 (比 v1 略增, 多了 tab 状态)
  • 迁移 ~30 行: 启动时把旧 NS.COMMANDS 按 cmd.protocol 归并, 老 v1 配置自动升级
  • 删除 ~40 行: "命令管理" 独立 modal 退役 (工具栏按钮移除, 函数保留作兼容)

总计 ~320 行新增 + 70 行迁移, 比 v1 多了约 30%, 主要花在向导的状态机和 modal 之间的交互上。

7下一步 — 还有啥要调的?

几个待你确认的细节

  • 命令详情面板：是常驻在 commands tab 下方 (我现在画的样子), 还是改用「点编辑按钮 → 弹新建命令 modal 的复用版」?
  • 复制协议：要不要这个功能? (我列了, 但你可能不需要)
  • 字段命名复用：新建命令时, 字段名输入框要不要给「复用已有命名」的下拉提示 (cell_1_v 等)? 还是完全自由命名?
  • 命令管理总览：用户偶尔可能想「所有协议所有命令的扁平视图」调试某个 ID 在哪。这个要不要单开一个「命令索引」modal?
  • 导入命令 JSON：协议编辑器里加个「导入 JSON 批量加命令」按钮? 还是保持纯手填?
